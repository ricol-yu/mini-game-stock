# WXS 滑卡验证工程

> 目的：在写任何业务代码之前，先证明「WXS 手势能跑满 60fps」。
> 这一步不通，整个技术路线要重估。**这个工程不承载任何游戏逻辑，是一次性验证件。**

## 为什么它能在 Windows 上做

WXS 跑在微信的渲染层，和操作系统无关。Windows 版开发者工具 + 一台手机做的真机预览，
就是完整链路。**跟 Mac 没有任何关系。**

之前说「去 Mac 上验」是误判：当时以为开发环境只在公司那台机器上。
真正的前提只有两个——装了微信开发者工具、有一个能用真机预览的 AppID。

## 前置（10 分钟）

**1. 装微信开发者工具**

https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html

选 Windows 64 位稳定版。装完用微信扫码登录（登录的账号要有这个项目的开发权限）。

**2. 拿一个能真机预览的 AppID**

三选一：

| 方式 | 能否真机预览 | 说明 |
|---|---|---|
| 测试号 | ✅ 可以 | 官方文档明确支持。访问 https://developers.weixin.qq.com/miniprogram/dev/devtools/sandbox 微信扫码即得，无需注册 |
| 正式 AppID（个人主体） | ✅ 可以 | 微信公众平台用没绑定过的邮箱注册，免费，5 分钟 |
| 游客模式（`touristappid`） | ❌ 不行 | 只能模拟器。工程里默认填的是这个，跑模拟器够用，但测手感必须换掉 |

**优先级：先用测试号。** 手感验证不需要正式账号，也不用等类目想清楚。

拿到之后，把 `project.config.json` 里的 `"appid": "touristappid"` 改成你的 AppID。

## 怎么跑

**第一步：模拟器（验布局）**

开发者工具 → 导入项目 → 目录选 `spike/wxs-swipe` → 填 AppID → 导入。

看四根属性条、卡面、印章位置对不对。**这一步不验证手感，别在这里下结论。**

**第二步：真机预览（验手感，这才是重点）**

工具栏点「预览」，手机微信扫码。想看日志的话，手机上点右上角胶囊 → 打开调试。

手机和电脑不在同一 WiFi 也通常能预览（预览包是走微信服务器的）。
如果一直加载不出来，再考虑真机调试——那个才要求同局域网。

**第三步：滑五次，看数字**

模拟器里用鼠标拖拽也能滑，但**只有手机上的数字有意义**。

## 要看的四个数

滑完之后底部面板会显示：

| 指标 | 正常值 | 说明 |
|---|---|---|
| 帧间隔（平均） | 14～18ms | 约 60Hz。≤ 12 说明是高刷屏，更好 |
| 帧间隔（最大） | < 34ms | 超过就是掉帧。偶尔一次可接受，频繁就要查 |
| 估算 fps | 55～60 | 手机 120Hz 屏会到 100 以上 |
| WXS 单帧耗时 | < 1ms | 这是从 WXS 调 `setStyle` 到返回的耗时。超过 1.5ms 说明渲染压力大 |

**判据只有一条：滑起来跟手，手指和卡片之间没有可见延迟。**
数字是辅助，不是标准。手感不对但数字漂亮，说明「跟手系数」调得不对，不是性能问题。

## 代码结构

```
wxs-swipe/
├── wxs/gesture.wxs          手势核心：所有帧级操作都在这里
├── pages/swipe/index.wxml   bindtouch* 绑到 WXS 函数，change:prop 做重置
├── pages/swipe/index.wxss   卡面样式，从 prototype.html 照抄
├── pages/swipe/index.js     只有换卡和显示数据，无手势逻辑
└── project.config.json     AppID 在这里改
```

**关键设计**：`touchmove` 里零 `setData`。WXS 直接 `selectComponent().setStyle()`，
只有 `touchend` 时用一次 `callMethod` 把测量数据丢回逻辑层，换卡再一次 `setData`。
一次完整划动 = 2 次通信。这就是能做到 60fps 的原因。

## 已知的不确定点（跑通了请回写结论）

这几处我没法离线验证，需要真机确认：

1. **`callMethod` 在 Page 上是否生效** —— 官方示例多用于 Component。
   如果 `onGesture` 不触发（数字一直是 `—`），把页面改成 Component 即可，其余代码不动。
2. **WXS 事件对象的触摸点字段** —— 代码用的是 `touches[0].clientX`。
   如果拿到 `undefined`，换成 `pageX`。改 `gesture.wxs` 里两处即可。
3. **CSS 变量在 WXSS 里是否可用** —— 这里刻意全用字面色值，避免变量干扰手势验证。
   正式工程要用变量的话，需要单独验一次。
4. **`will-change: transform` 是否被支持** —— 不支持也无害，会被忽略。

2. 手感参数（`TH` 阈值、`ROT` 旋转角、阻尼系数）确定后，记进 `docs/devlog/`
