### 一个必须先摆出来的算术

一局 = 60 天 × 每天 3 张 = **180 次滑卡**。

而现在的选卡逻辑是 `c._used < 2`，也就是**每张卡单局最多出现 2 次**：

```
63 张 × 2 = 126  <  180
```

池子在一局末尾会被抽空，然后 `_used` 清零重来。

**结论：现在的问题不是"内容不够丰富"，是"连一局不重复都做不到"——平均每张卡一局里要出现 2.9 次。**

《王权》(Reigns) 是 750 张。但它是多君主、多轮继承、大量一次性角色堆出来的，结构不同，不能直接照搬数字。我们该对齐的是它的**体感密度**，而体感密度由这条算式决定：

```
单局抽数 180  →  卡池 ≥ 180 才可能一局不重复
                → 卡池 ≥ 260 时，跨 3 局才明显重复
```

所以目标定成阶梯：**v1 上线 220 张 → v1.5 到 350 → v2 再谈 500**。先别想 750。

## 1. 你列的六件事，逐条补全

### ① 卡片数量 —— 但真正先要做的是"能批量生产"

不是"多写 100 张"。63 张手写在 `cards.json` 里还能管，220 张就必须有生产线，否则每加一张都在赌数值有没有崩。

**要建的三样东西：**

| 工具 | 作用 | 判据 |
|---|---|---|
| `tools/validate-cards.js` | 校验：id 唯一且非顺序、字段完整、`when` 语法可解析、效果键白名单、数值上下限、文案字数、`did:` 引用的前置卡是否存在 | 一条不合格就退出码 1，能进 CI 更好 |
| `tools/simulate.js` | 无头跑 N 局（目标 10 万局）：结局分布、各属性死因占比、**每张卡的出现率与"从没被抽到"的比例**、单局重复率、支配选项率 | 输出一份 JSON 报告，跑完 10 万局 < 60 秒 |
| 管理表升级 | `cards-manager.html` 支持新增 / 复制 / 按 tag 筛 / 批量改数值 / 显示校验错误 | 能在里面从零写完一张卡并导出通过校验 |

**分配建议（220 张）**：家庭 34 / 市场 30 / 风险 26 / 职场 24 / 自己 22 / 人情 18 / 收入 18 / 决策 16 / 意外 14 / 隐藏 18。

注意 `意外` 只有 1 张、`收入` 3 张、`决策` 3 张——这三类是节奏调节器，缺了整局会变得可预测。

**角色复用比加新角色重要。** 39 个角色只出场一次，等于 39 张一次性卡。Reigns 的黏性来自"同一个讨人厌的顾问又来了"。目标：**20 个常驻角色各 6–10 张（约 140 张）**，剩下 40 张给一次性角色，其余给隐藏卡。这样玩家能记住人，而不是记住卡。

### ② 卡片关联性 / 隐藏卡 —— 先扩 DSL，再写卡

现在 `when` 只能判属性与状态（`has:fired`、`mind<30`、`equity>cost*0.85`），**无法表达"上次那件事你选了哪边"**。

要做的是给 DSL 加三个谓词，而不是给每张卡写函数：

| 谓词 | 含义 | 例 |
|---|---|---|
| `did:fam_mortgage_01.r` | 这张卡你选了右边 | `did:fam_mortgage_01.l` |
| `seen:fam_mortgage_01` | 见过（不分左右） | 用于"后续追问" |
| `pick:tag:家庭>=5` | 某类倾向统计 | 用于"你一直选家里" |

三层递进的关联设计：

1. **直接前置**（最易做、效果最好）：A 选右边 → 三局内 B 出现。失败感/后果感都强。
2. **数值门槛**：`equity>80000; mind<30` 才出现的"有钱但快崩了"专属卡。
3. **状态门槛**：已有 `addst`/`unst`，复用即可。

**隐藏卡必须可发现，否则等于没做。** 三个要求：
- 图鉴里留位，未解锁显示剪影 + 一句模糊提示（"有人的手机再没响起过"）
- 每张隐藏卡必须能被仿真器证明可达（10 万局里至少出现 1 次）
- 首局不能依赖隐藏卡提供内容——隐藏卡是第二、三局的奖励，不是第一局的地基

**风险**：隐藏卡越多，第一局的可见内容越少。建议 v1 隐藏卡不超过 **18 张（8%）**。

### ③ 美术素材 —— 入口和规范我来定，但有个省 3/4 工作量的做法

**关键判断：按角色出图，不要按卡出图。**

63 张卡只有 48 个角色；220 张卡如果沿用现有角色体系，角色数大约 60–70 个。按角色做素材，工作量从 220 降到 65，而且同一角色反复出现时长相一致——Reigns 就是这么做的。

目录与命名（**全小写拼音，不用中文、不用 emoji、不用空格**）：

```
assets/
├── manifest.json              ← 素材清单，唯一真源
└── avatars/
    ├── laopo.webp             ← 老婆
    ├── laoban.webp            ← 老板
    ├── yueni.webp             ← 你的票
    └── ...
```

规格：

| 项 | 值 | 理由 |
|---|---|---|
| 显示尺寸 | 62rpx 圆形（≈31pt） | 现原型 `.av` 是 31px，WXSS 里乘 2 |
| 导出尺寸 | **128×128**（可向下兼容 2x/3x） | 3x 屏需要 93px，128 有余量 |
| 格式 | **webp**，q80，透明底 | 小程序支持；同质量比 png 小 60% |
| 单张体积 | ≤ **12KB** | 128×128 线稿完全够 |
| 线条 | 视觉重 2px @128 | 太小在 62rpx 下会糊成一团 |
| 背景 | 无 | 卡面本身是白底，带底色会显脏 |
| 色彩 | 单色 + 1 个强调色 | 保证 65 张风格一致 |

`manifest.json` 结构（这份文件是给生图 AI 和生产流程共用的接口）：

```json
{
  "version": 1,
  "style": "线稿 / 单色 + 一个强调色 / 无背景 / 不写实",
  "items": [
    {"whoId": "laopo", "name": "老婆", "file": "avatars/laopo.webp",
     "status": "todo", "desc": "三十多岁，疲惫，仍在意你", "note": ""}
  ]
}
```

`status` 四态：`todo` → `draft`（AI 已出图）→ `approved`（你看过）→ `shipped`。页面只加载 `approved`/`shipped`，`todo` 自动回落到文字首字，**不会因为缺图开天窗**。

生图 prompt 模板，统一前缀保证一致性：

```
正方形头像，圆形裁切安全区，{desc}，
黑白线稿加单一强调色（{color}），无背景，线条干净，无阴影，
扁平插画风格，不要 3D，不要写实照片，不要文字
```

**包体账（这条决定架构）**：

- 65 张头像 × 12KB ≈ **780KB** → 可以进主包，但已经吃掉 4MB 的五分之一
- 若再给 220 张卡出卡面插画（哪怕 30KB 一张）= 6.6MB → **必然超包**

所以：**头像进主包；卡面插画、结局插图、BGM 一律走 CDN 或分包**。这个边界现在就定，不要等超包了再拆。

**先只做 10 张试点**，确认风格统一、在真机 62rpx 下能看清，再批量跑剩下的。

### ④ 动画 / 音效 —— 先写清单，再谈打磨

**音效清单（6 个，够用）**：滑左 / 滑右 / 松手回弹 / 日结算 / 状态触发 / 结局。
格式 mp3 48kbps 单声道，单个 ≤15KB，合计 ≤90KB。

**BGM**：1 首 60 秒可循环，48kbps ≈ 360KB → 走 CDN。循环点必须做无缝（导出时裁掉首尾静音）。

三条硬约束：
- 必须有静音开关，且**首次进入不自动播**（iOS 要求用户交互后才能播）
- 音效不能压在滑卡动画的关键帧上，松手之后再响，否则滑动会"变重"
- 日结算音效是唯一的"每次必听"，其余都要能忍受 180 次

**动画**：全部走 WXSS `transition` / `animation`，不用 JS 逐帧。清单：卡片飞出（180ms ease-out）、属性条宽度变化（300ms）、数值跳动、印章淡入、结局上浮。手感参数（时长/缓动）等 WXS 验证通过后再定，现在定了也会推翻。

### ⑤ 主玩法之外的系统 —— 顺序很关键

**先存档，再成就。** 没有存档的成就，等于每次打开都是新玩家。

| 系统 | 现在 | v1 目标 | 为什么排这个位置 |
|---|---|---|---|
| **存档** | 无 | 局内进度 + 跨局元进度，`wx.setStorageSync`，单局 <5KB | 60 天局被打断就白玩，这是留存第一杀手 |
| **新手引导** | 无 | 前 3 张卡固定，第 1 张教左滑右滑，第 2 张让属性条明显动一次，第 3 张展示一个状态 | 前 5 张卡决定留存，不能靠随机卡运气好 |
| **结局系统** | 13 个 | 24 个 + 结局图鉴（已解锁/剪影） | 结局是分享素材，也是重开动机 |
| **成就** | 无 | 30 条：行为 / 数值 / 结局 / 隐藏 四类 | 给"再开一局"一个具体理由 |
| **卡牌图鉴** | 无 | 220 格，按 tag 分页，未解锁剪影 | 收集感 + 让隐藏卡"可被发现" |
| **分享** | 无 | 结局海报（Canvas 绘制 → 保存/转发）+ 小程序卡片分享 | 广告变现需要流量，流量来自分享 |
| **设置** | 无 | 音效/音乐开关、清档（二次确认）、版本号 | 上线审核项 |
| **埋点** | 无 | 开局 / 每日结算 / 每张卡的选择 / 结局 / 广告观看 | 不看数据无法调平衡 |

**多局元进度**（Reigns 真正的留存设计）：第二局解锁 2–3 个常驻角色的新卡线。这个不需要新系统，只需要"跨局 flags"——存档里多存一个 `meta` 对象即可。

### ⑥ UI 打磨 —— 等真机，别在浏览器里定

原型是浏览器里调的，小程序里字号、行高、圆角的手感都不一样。顺序：

1. 先定 design token（颜色 6 个、字号 5 档、间距 4 档、圆角 2 档），写进一份 `docs/design/tokens.md`
2. 再改布局：安全区、刘海、小屏（iPhone SE 375×667）、大字体模式
3. 最后才是动效节奏

**不要现在就深入打磨**——卡池和系统都会改布局，现在打磨等于白做。

## 3. 顺序与依赖

```
P0  [阻塞·你]  spike 真机手感验证
                ↓ 通了才能定交互动效与手感参数
P1  [地基·AI]  id 重构 → schema v2 → 校验器 → 仿真器
                ↓ 没有这层，铺量就是堆垃圾
P2  [内容]     63 → 220 张（按 tag 缺口分配）
                ↓ 卡够多了，关联才有意义
P3  [关联]     DSL 加 did:/seen:/pick: → 前置链 → 18 张隐藏卡
                ↓
P4  [素材]     规范 + manifest + 首批 10 张 → 全量 65 张
                ↓（P4 可与 P2/P3 并行，产物是图片，不冲突）
P5  [系统]     存档 → 引导 → 结局 24 → 成就 → 图鉴 → 分享 → 埋点
                ↓
P6  [上线]     类目 / 隐私协议 / 广告位 / 灰度 10 人 → 收集数据 → 放量
P7  [打磨]     token → 布局适配 → 动效（最后做）
```

**为什么地基必须排在铺量前面**：id 一改，所有已有卡都要动一次。220 张之后再改，就是 220 次返工 + 一次全量数值复验。

**为什么美术可以并行**：它的输入是 `manifest.json`，输出是图片文件，不碰 `cards.json`，不存在文件冲突。

## 4. 卡牌 schema v2（P1 要落地的东西）

```json
{
  "id": "fam_mortgage_01",
  "who": "老婆",
  "whoId": "laopo",
  "tag": "家庭",
  "text": "这个月房贷 6,800。你看着办。",
  "when": "day>3; no:did_mortgage",
  "window": { "minDay": 1, "maxDay": 55 },
  "weight": 1,
  "once": false,
  "hidden": false,
  "left":  { "label": "先拖两天", "effects": { "mind": -5, "social": -5 } },
  "right": { "label": "出 5,500", "effects": { "spend": 5500, "social": 6, "mind": 2 } }
}
```

新增字段只有三个半，其余沿用现有：

| 字段 | 作用 | 默认 |
|---|---|---|
| `id` | 语义化、不可变、唯一 | 必填 |
| `whoId` | 头像文件名，解耦"显示名"和"素材名" | 由 `who` 映射 |
| `window` | 出现天数窗口，控制节奏（前期事件不会第 55 天才来） | 1–55 |
| `weight` | 抽卡权重，调节稀有度 | 1 |
| `once` | 一局只出现一次 | false |
| `hidden` | 图鉴不露名字 | false |

`when` 扩展三个谓词：`did:<id>.<l|r>`、`seen:<id>`、`pick:<tag>><n>`。**不引入 JS 函数**——这条已经写进 `AGENTS.md`，别破例。

## 5. 什么时候算"可以开始铺量"（门槛）

铺量前必须全部满足，否则后面每加 50 张就要返工一次：

- [ ] 校验器能拦住全部 8 类错误（有测试用例）
- [ ] 仿真器 10 万局 < 60 秒，输出含"每卡出现率"
- [ ] **单局重复率 ≤ 25%**
- [ ] **每个结局触发率 ≥ 0.5%**（现在完全没测过，13 个结局的真实分布是未知数）
- [ ] **支配选项 ≤ 5%**（现在：30 张纯数值可比卡里 14 张，47%——一边在所有维度上都不差于另一边。
      检测是启发式的：只比方向、不分权重、忽略数值耦合，所以是下限而非判决）
- [ ] 隐藏卡可达性 100%（10 万局里都出现过）
- [ ] 存档能跨"杀掉小程序进程"恢复
