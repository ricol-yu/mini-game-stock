# 开放局 + 次数制改造设计（2026-10-26 定稿，批 2 之前实施）

> 状态：已与产品拍板方向。本文档是 Windows 端实施的依据，实施前通读。

## 1. 背景与目标

- 用户体感：60 天不够玩，卡池持续扩容后「没体验到最新内容就结束了」。
- 变现目标：纯 IAA（激励视频），靠**高难度 + 每日次数限制**驱动广告与分享。
- 两个诉求方向相反（长局 vs 死得快），解法：**开放局给深度，次数制给变现**，
  面向不同人群，用「天数即分数」缝合。

## 2. 局结构：完全开放（拍板结论）

- 取消第 60 天清算。卡一直发、日子一直过，直到两个终点之一：
  1. **死因结局**：四属性任一归零（心态/社会/风险/净资产，各自死法已有雏形）；
  2. **达成型结局**：净资产冲过目标线 = 财务自由；提前清仓跑路 = 上岸（数值线待定标）。
- 压力随天数递增保证苟不住（见 §3），每局必有终点，终点由玩法而非日历决定。
- 结算页主数字 = **生存天数**（分数），接好友排行（二期）。
- 「活满 60 天」等旧结局评价全部改为死因/达成叙述。

## 3. 压力引擎（开放局的承重梁）

没有时间压力的开放局 = 无限苟。压力必须随天数单调上升：

| 压力源 | 机制草案 | 定标方式 |
|---|---|---|
| 通胀 | 生活成本按天数复利递增（如 +0.4%/天，拐点待仿真扫） | simulate.js 扫系数 |
| 市场波动 | 牛熊振幅随天数放大，熊更熊 | 引擎侧乘 days 系数 |
| 精力磨损 | 精力上限随天数缓慢衰减，或回血手段概率递减 | 三件套对照 |
| 职场年龄线 | 35 岁危机类 window 卡（推迟到长局后段触发） | 批 2 新卡 |

**「举步维艰」的正确形态**：不是数值碾压死玩家，而是第 40 天起每个选择都在割肉。

### 3.5 难度曲线：先甜后苦（10-26 二次拍板）

三条设计原则：

1. **难度上升 ≠ 数值变负**，而是「好选项变稀、代价变重、回血变少」——
   靠发卡配比漂移实现（见下），数值只做辅助。
2. **前期甜头是投资**：让玩家在压力到来前学会系统、赚到第一次快钱、认识主要角色。
3. **艰辛要有脸孔、有方向**：压力尽量通过生活事件表达（房租涨/爸妈体检/随份子），
   不做抽象扣钱；财务自由进度前中期就可见，苦但不是纯苦。

三阶段曲线（生存压力上行 × 卡池甜度下行，交叉）：

| 阶段 | 天数 | 压力 | 发卡配比 | 体验目标 |
|---|---|---|---|---|
| 甜头期 | 1–20 | 通胀豁免、波动低 | 收入/机会卡权重↑，意外/大额支出↓；各关系线触发层卡提前铺 | 学会系统、第一次赚快钱、见到主要角色 |
| 现实期 | 20–50 | 通胀开始咬、波动放大、大事线开窗 | 两难卡为主，家庭/职场开始要钱要精力 | 乐趣从「赚」转向「平衡」；财务自由进度可见 |
| 艰辛期 | 50+ | 全面上升、回血手段变稀 | 高压卡（意外/暴跌/大额）权重↑，甜卡变稀 | 生存即成就，天数分数在此拉开 |

**发卡实现**：洗牌袋的分层交错已按 tag 均匀铺，改造点 = 每类卡的抽样权重
按 day 段漂移。权重表进 `data/cards.json`（每张卡可选 `phase` 字段或按 tag 全局权重表），
引擎侧加权抽样、仿真侧可复现 —— 不做隐藏逻辑。

**数值护栏**（三件套对表用，2026-10-26 按实测微调）：

- 会玩玩家生存曲线：中位死亡 ~day 45–60，p90 ≥ 100 天
- 会玩前 30 天死亡率 **≤ 35%（机器人口径）**——原定 <10% 对机器人太严：
  它们不看未来现金流，真人会。真人预期约一半。
- 乱滑仍 30 天内死透（下限不变，变现基本盘）
- 60 天后仍存活的局 ≥ 15%（开放局的内容深度要有够多的人体验到）

## 4. 次数制 + 任务系统（拍板结论）

- 广告不是局内复活，是**再来一局的资格**（用户原话：「让玩家可以重新」）。
- **每日免费次数**：3 次/天起步（可调，上线后看数据）。
- **获取额外次数**：看激励视频 +1 次；分享 +1 次；邀请好友 +N 次（任务系统承接，二期做任务中心）。
- 局内死亡不复活 —— 死亡即结算，硬核感靠这个保住。
- ⚠️ 防滥用边界：分享/邀请必须走微信开放能力校验，防刷；激励视频回调服务端校验。

## 5. 难度目标（先量后调，2026-10-26 基线）

当前（Windows hardmode 后）3000 局基线：

| 策略 | 通关率 | 平均天数 |
|---|---|---|
| 随机乱滑 | 7.4% | 29.7 |
| 永远左滑 / 右滑 / 老好人 | 0% | 12.7–24.1 |
| 会玩 | 53.2% | 45.4 |
| 会玩·maximin | 51.1% | 42.7 |

技巧回报 x7.19（目标 ≥2.0x，已远超）。

开放局后的目标区间（通关重定义为「达成任一好结局」）：

- 随机乱滑：30 天内死透（现已接近）
- 会玩：**活着但难受**，达成好结局 20–35%（当前 53% 偏松，压力引擎上来后自然压低，先不动）
- maximin 同区间，且平均生存天数应是乱滑的 2 倍以上

调参顺序：先上压力引擎拿新基线 → 再决定要不要动生活成本系数。
**改卡三步**（validate → simulate → 对比基线）不变，另跑 check-repeat。

## 7. 实施顺序建议

1. 引擎侧：去 60 天硬清算 + 压力引擎三件（通胀/波动/磨损）+ 结算页天数

4. 次数制 UI（每日 3 次 + 看广告 +1）

## 8. 实施记录：第 1–3 步已完成（2026-10-26 晚，Mac）

| 项 | 落地方式 |
|---|---|
| 去 60 天清算 | `MAX_DAY=360` 仅作硬上限；日推进不再有日历终点 |
| 通胀 | `INFL_FROM=20, INFL_RATE=0.008`：前 20 天 120/天，之后 `200×1.008^(day-20)`，第 21 天弹「房租涨了」 |
| 波动放大 | `VOL_GROW=0.003`：`vol = 0.042×(1+(day-20)×0.003)` |
| 发卡漂移 | `PHASE_GATE`：甜头期(≤25)压 意外50%/风险50%/市场40%/家庭20%/人情15%；艰辛期(>55)压 收入60%/自己30%/人情25%。**在 bagShuffle 抽卡，不碰扫描逻辑**（在 bagFind 里拦会让同类相邻 13%→33%、垫层预览出现重复）|
| 开局缓冲 | `INIT=20000`（现金 11,000 + 底仓 9,000）：实测 9,000 现金会被甜头期卡片支出在 19 天打死 |
| 结局换代 | 死因 8 个保留 + 达成型：自由(≥80k)/上岸(清仓还清且 ≥1.5×INIT)/两个人(结婚+社会70+60天后)/熬成精(150天后仍为正)/一次都没动(120天无交易) |
| 工具 | 校验器 window 上限 60→360；simulate/check-policy 循环 60→360 天；通关口径=活过 60 天；check-policy 新增生存分布行（p50/p90/<30天死/≥60/≥120） |

**实测（2000 局×6 策略 + 5000 局结局）**：maximin 中位 55 天 / p90 132 / ≥60 天 47.9%；
乱滑均 30.9 天、p50 28；技巧回报 x8.9；前 60 天单局重复 0%。全部数字见 `baseline.md`。

**未做**：精力磨损（精力上限随天数衰减）——当前 p50/p90 已达标，先不叠第四层压力；
若上线后「会玩活太久」，优先加这一层，而不是再压生活成本。
