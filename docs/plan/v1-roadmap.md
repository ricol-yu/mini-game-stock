## 工程结构建议（贯穿）

- **现在**：继续单文件 prototype.html + 工具链（validate/simulate/smoke-ui）——双端协作、
  冒烟测试、sync 流程都建在这个结构上，别为了"正式"推翻。
- **迁小程序前**：新增一个构建步骤 `tools/build-weapp.js`：把 prototype 的 HTML/CSS/JS
  拆进小程序页面骨架，CARDS 数据直接打包 cards.json。**注意：微信"小游戏"是 canvas 无 DOM，
  本作是 DOM 重度——要走"微信小程序"（webview）路线，别选小游戏容器。**
- **红线沿用**：cards.json 唯一真源；id 不可变；when 三处解析器同步；改完必跑 validate + smoke-ui。

## 与素材的关系

P0 全部不需要美术素材（弹窗/存档/菜单/音效框架都是纯工程）。
素材第一批到位后进 P1-8 视觉换代。**两条线可以并行：你出画，我出壳。**

> 素材规范以 v2 轻量版为准（2026-10-28 重写）：第一批只需 **11 个文件 ≈ 500KB**
> （5 个主角图 + 老婆 4 张差分 + 主菜单背景 + 1 个音效），卡面人物位 640×400，
> 不做整屏立绘。占位机制已做进卡面，素材没到也能玩。
