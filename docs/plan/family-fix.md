# 家庭线三项修复方案（2026-10-26）

> **已实施（2026-10-26 晚）**。用户拍板：彩礼右项用「先不结，再攒攒」、认真玩 30% 结婚 / 15% 有孩子、
> tag 叫「伴侣/家人/孩子/宠物/房子」、恋爱期窗口收到 100 天。
> 实施记录与实测数据见 `docs/devlog/2026-10-26.md`「五轮」。
> 落地结果：**结婚 29.8%/31.7%、有孩子 14.0%/15.5%、插队 63%→29%、同类相连 32.5%→3.8%**。
> 实施中发现并修掉两个额外 bug（`no:did:` 被误判为回响卡、无 window 的链卡被插队排序饿死）。

> 起因：HANDOFF 留了两条已知问题（同类卡扎堆、婚姻线走不通）。动手前先把它们量化，
> 结果量出第三个更严重的问题（**开放局了，但 43 张卡的窗口还是 60 天**）。
> 本文只提方案，等拍板后实施。

---

## 0. 先看测出来的三个事实

### 事实 1：家庭卡占了抽卡的 65%，因为关联卡插队没有节流

| 指标 | 随机乱滑 | 认真玩（爱优先） |
|---|---|---|
| 卡池里家庭卡占比 | 35.8% | 35.8% |
| **实际上场占比** | 30.8% | **65.1%** |
| 家庭卡里"关联卡插队"的比例 | 81.9% | **95.8%** |
| 关联卡插队占全部抽卡 | 29.4% | **63.0%** |
| 同一类卡连着来的比例 | 32.5% | 32.5% |
| 家庭卡两次之间的间隔在 1–2 天内 | 92% | 92% |

原因不是"家庭卡太多"，是 `pick()` 里关联卡**无条件优先**：只要条件满足就插队，
而且插队不走「同类不连」的检查（`bagFindChain` 没有 avoidTag 参数）。
会玩的人一旦开始谈恋爱，每天都有一堆"该回响"的家庭卡排队，普通卡（市场、职场、决策）被挤到 4%。

**这解释了为什么你觉得"卡片关联有点错乱"——不是关联错了，是关联卡把牌堆淹了。**

### 事实 2：婚姻线卡在彩礼，不是"很难"，是"必死"

1500 局对照（同样的卡池、同样的行情种子）：

| 漏斗 | 随机乱滑 | 认真玩（爱优先） |
|---|---|---|
| 有女友入口 | 100% | 100% |
| 确定关系 | 87.9% | 100% |
| 见家长 | 42.6% | 100% |
| 彩礼 | 30.7% | 100% |
| 婚礼 | 11.3% | **0%** |
| 有孩子 | 2.2% | **0%** |

**全力爱你的人，一个都结不成婚。**

彩礼那一刻的真实状态（1500 局平均）：第 13 天，现金 ¥5,445、持仓 ¥6,711、净值 ¥12,156、**精力 4**。
而这张卡的"借，也要给"要 **借 60,000 + 掏 28,000**——掏的这 28,000 直接把净值打成负数，当场穿仓。
改之前没人告诉玩家：这个选项等于自杀。

精力也是同一把刀：整条链见家长 −24、彩礼 −20、婚礼 −32，合计 −76，而精力预算是 50、
回血只能靠随机的休息卡。走到彩礼时精力只剩 4，后面还有婚礼 −32 在等着。

### 事实 3：开放局了，但 43 张卡的窗口还停在 60 天

| 项目 | 数字 |
|---|---|
| 有 window 的卡 | 43 张，**上限全是 40–60** |
| 无 window 的卡 | 105 张 |
| 第 61 天起永久消失的卡 | **43 张**：家庭 28、职场 12、收入 1、意外 1、市场 1 |

也就是说：**第 60 天之后，婚姻线、孩子线、父母后段、职场整条线全部蒸发**，只剩 105 张卡循环。
这正是"卡池扩容后没体验到最新内容就结束了"的另一个原因——不是天数不够，是内容提前退场。

### 顺带的定标参照：玩家到底有多少钱

认真玩 800 局，净值分布：

| 天数 | p10 | p50 | p90 |
|---|---|---|---|
| 第 10 天 | 11,711 | 16,941 | 20,710 |
| 第 30 天 | 4,327 | 12,660 | 22,622 |
| 第 60 天 | 9,072 | 18,084 | 28,532 |
| 第 90 天 | 3,549 | 12,063 | 22,512 |

**结论：单张卡"当场掏现金"的上限应该压在 6,000–8,000（净值 p50 的一半）。**
超过这个数就必须用负债/分期表达，否则一张卡就是一条命。

## 1. 方案 A：家庭 tag 拆成五个

现在一个"家庭"标签扛了 53 张卡（35.8%），分层算法没法把它们摊开——同一类卡越密，相邻概率越高。
按人物拆开后最大的桶只剩 19%。

| 新 tag | 张数 | 卡池占比 | 包含 |
|---|---|---|---|
| **伴侣** | 28 | 18.9% | 女友 13 + 老婆 15 |
| **父母** | 10 | 6.8% | 老妈 6 + 老爸 1 + 丈母娘 3 |
| **子女** | 10 | 6.8% | 孩子 7 + 老师 3 |
| **宠物** | 3 | 2.0% | 你的猫 |
| **住处** | 2 | 1.4% | 房东 |

- 卡 id 一律不动（`fam_*` 保留，几十条 when 引用着它们，改名风险远大于收益）
- 卡面右上角标签会变成「伴侣 / 父母 / 子女」——玩家一眼知道这条线在讲谁，比"家庭"清楚
- 难度曲线的阶段门控跟着改键名：甜头期照样压这几类，压的力度按类微调（见下表）

```js
// PHASE_GATE 改后
early: { until: 25, skip: { "意外":0.5, "风险":0.5, "市场":0.4,
                           "伴侣":0.15, "父母":0.2, "子女":0.3, "宠物":0.2, "住处":0.2, "人情":0.15 } }
late : { from : 55, skip: { "收入":0.6, "自己":0.3, "人情":0.2, "伴侣":0.1 } }   // 后期关系也变贵
```

## 2. 方案 B：关联卡插队要排队（这是"扎堆"的正解）

三条规则，全在 `pick()` / `bagFindChain()` 里，不动洗牌袋：

1. **隔天**：昨天已经插队过 → 今天必须出普通卡（链卡占比天花板从 63% 降到 ≤50%）
2. **同类不连**：插队也要看 `_lastTag`，同一分类的卡不连着上（这条直接掐死 92% 的"家庭连着来"）
3. **先过期的先出**：多张链卡都能出时，选 window 结束日最早的（现在按袋子顺序随机，快过期的反而可能被跳过）

预期效果（实施后要对拍验证）：

| 指标 | 现在 | 目标 |
|---|---|---|
| 关联卡插队占抽卡（爱优先） | 63.0% | 30–40% |
| 同类卡连着来 | 32.5% | <20% |
| 家庭/伴侣相邻间隔 1–2 天 | 92% | <60% |

**风险与兜底**：链卡排队会推迟叙事回响（今天做的事可能隔一天才有反应），所以窗口必须放宽（见方案 C），
并且 `cap=1` 的链卡一局只能出一次——排队不能把它们憋过期。

## 3. 方案 C：婚姻线重新定价（按"净值 p50"定价，不按剧情定价）

原则：**一条链走完的总现金支出 ≈ 2 个半月的工资结余**，中间必须让玩家有"攒钱再结婚"的余地。

| 卡 | 现在（左/右） | 改成 | 理由 |
|---|---|---|---|
| 见家长 | 掏 3,000 / 精力 −24 | **掏 1,500 / 精力 −14** | 见面礼不该等于净值的 1/5 |
| **彩礼** | **借 60,000 + 掏 28,000** / 掏 10,000 | **左：掏 8,000 + 借 12,000（先付一半，剩下打欠条）**<br>**右：先不结，再攒攒（不花钱，社会 −10）** | 原左项必死；右项改成"拖延"——这张卡可以再来一次（cap 2），攒够了再面对 |
| 婚礼 | 掏 15,000 / 掏 3,000，精力 −32/−28 | **掏 10,000 / 掏 2,000，精力 −18/−14** | 婚礼当天累，但不该把精力清零 |
| 首付 | 借 40,000 | **借 25,000** | 买房仍是重决策，但不至于一次锁死 |
| 房贷 | 掏 5,500 | **掏 3,500** | |
| 怀孕 | 掏 5,200 | **掏 3,000** | |
| 补习班 | 掏 3,900 | **掏 3,000** | |
| 兴趣班 | 掏 6,800 | **掏 4,500** | |
| 三张约会卡 | 精力 −10 / −10 / −12 | **−8 / −8 / −10** | 恋爱不该比加班还耗人 |

**彩礼两条路的长期后果要分开**（否则"借"永远更优，因为社会 +12）：

- 左（借 2 万、先付 1.2 万）：社会 +12、关系顺、但**负债每天滚利息**（0.15%/天 × 风险系数），
  婚后每月还有房贷——账是明面上的。
- 右（再攒攒）：不花钱、社会 −10，但这张卡**会再来一次**（第二次来的时候玩家手上有钱了）。
  如果一直拖，婚礼卡要等到彩礼结算后才出现，等于**婚期被你自己推迟**——这就是惩罚本身。

**精力账重算**：约会 −8、生日 −16、确定 −10、见家长 −14、彩礼 −12、婚礼 −18，全链 −78（原 −108），
配合 50 点预算 + 休息卡，走完全程需要主动穿插休息——仍然紧，但不是死路。

## 4. 方案 D：时间窗续期（开放局的欠账）

43 张卡的 window 上限按叙事阶段重排，不再统一卡在 58/60：

| 类型 | 卡 | 现在 | 改成 |
|---|---|---|---|
| 恋爱期（约会/生日/见家长/试探/攒钱/冷战） | 8 张 | [1,58] 一带 | **[1,150]** |
| 彩礼 | 1 张 | [12,58] | **[20,150]** |
| 婚礼 | 1 张 | [16,58] | **[24,180]** |
| 首付 / 房贷 | 2 张 | [22,58] / 无 | **[30,240] / 无上限** |
| 怀孕 / 产检 / 孩子后段 | 6 张 | [12,58] 一带 | **[36,300] 一带** |
| 父母后段（老妈复查/老爸住院） | 2 张 | [12,58] / [30,58] | **[15,200] / [40,300]** |
| 职场链 12 张 | 12 张 | 40–58 | **[20,240] 一带** |
| 市场/意外 | 2 张 | 45–58 | **[30,300]** |

规则：**上限不再是"截止日"，而是"这条线最多能晚到什么时候"**。开放局里没有第 60 天，只有死。
（下限保留原值，避免开局就抛彩礼。）

## 5. 方案 E：补两张卡，让这条线自己转起来

1. **「她说今晚不聊股票」**（伴侣，`did:fam_queding_01` 之后，无 window）
   左「陪她早睡」精力 **+16**、社会 +6、心态 +3；右「再看一小时盘」精力 −6、心态 −2、风险 +3
   → 婚姻线自己的回血点，把"休息只能靠随机自己卡"变成"关系能养人"
2. **「欠条」**（伴侣，`did:fam_caili_01.l`，window [22,240]）
   左「这个月多还 2,000」spend 2,000、负债 repay 2,000、心态 +3；右「先还最低」repay 500、心态 −3
   → 彩礼的债有回响，不是借完就忘

## 8. 执行顺序（半天量级）

1. 改 tag（53 张）+ 同步 validate / build-manager → `validate` 全绿
2. 改 window（43 张）→ 扫描确认 60 天后无卡消失
3. 改 `pick()` 排队三条规则 → `check-repeat` 看相邻率
4. 重定价 8 张 + 加 2 张新卡 → `validate` / `check-dominance`
5. 全量对拍：3k 随机 + maximin + 婚姻漏斗脚本，与本文目标表逐项比对
6. 不达标就拧三个钮：插队间隔（1 天 / 2 天）、彩礼金额、window 下限
