# 2026-10-26（Mac / 夜）

## 开放局改造落地：去 60 天清算 + 压力引擎 + 结局换代

设计定稿在 `docs/plan/openend-design.md`（26f05a1 / 6748ba3），本条是实施记录。
完整数据见 `docs/plan/baseline.md`「开放局改造后基线」。

### 背景
用户体感：60 天不够玩，卡池扩容后「没体验到最新内容就结束了」；同时要提升难度
（举步维艰）以支撑 IAA 变现。方案：**局完全开放**（死因归零或达成结局才结束，
天数=分数）+ **次数制变现**（广告给「再来一局」的资格，不是局内复活）+ **先甜后苦的难度曲线**。

### 引擎改动（prototype.html）
1. `MAX_DAY` 60→360（仅硬上限）；日推进不再有日历终点
2. 通胀：`INFL_FROM=20 / INFL_RATE=0.008`，前 20 天 120/天（甜头期），之后
   `200×1.008^(day-20)`；第 21 天弹「房租涨了，菜价也涨了」
3. 波动放大：`vol = 0.042×(1+(day-20)×0.003)`
4. 发卡漂移 `PHASE_GATE`：甜头期压 意外/风险/市场/家庭/人情；艰辛期压 收入/自己/人情
5. 开局缓冲：INIT 18,000→20,000（现金 11,000 + 底仓 9,000）
6. 结局换代：死因 8 个保留；新增 上岸（清仓还清且 ≥1.5×INIT）/ 熬成精（150 天后为正）/
   两个人（条件改为 60 天后仍结婚+社会70）/ 一次都没动（120 天无交易）
7. 序幕教程去掉「60 天」措辞

### 踩坑（重要）
**phase 门控第一版写在 bagFind 扫描里，当场把洗牌袋打坏**：同类相邻 13%→33%、
同一角色相邻 3%→31%、垫层三张出现重复 15.8%。改到 bagShuffle（洗牌期把卡抽出这一轮）
后全部恢复（预览重复 0%、单卡一局最多 1 次）。**教训：抽卡算法的改动只能在洗牌期做，
不要在扫描路径上加随机分支。**

### 定标过程（三轮）
1. 初版（INIT 18,000 / 200 恒定）：会玩前 30 天死 41%，死因 70% 是钱（一无所有 46%+穿仓 24%），
   平均 19 天破产 → 甜头期不甜
2. 加开局缓冲 +2,000、前 20 天成本 120/天 → 41%→33.7%（maximin），仍不够
3. early 再轻压家庭/人情 + 「泡沫之后」要求活满 30 天 → 最终 33.7%，中位 55 天、p90 132

**机器人不看未来现金流，前 30 天死亡率 33.7% 已放宽判定**（真人应再低一档）。
精力磨损（第四层压力）本轮未加：p50/p90 已达标，留着做后续旋钮。

### 工具链
- `validate-cards.js`：window 上限 60→360
- `simulate.js`：循环 60→360；重复率口径改「前 60 天」；修复「活过60天重复率」算负数
- `check-policy.js`：循环 60→360；通关口径=活过 60 天；**新增生存分布行**
  （p50/p90/<30天死/≥60/≥120）——定标期主要看这个

### 实测
maximin：p50=55 / p90=132 / ≥60天 47.9% / ≥120天 15.2% / 前30天死 33.7%
乱滑：均 30.9 天 / p50=28 / 活过60天 5.4%；技巧回报 x8.9；伪选择 0%；前 60 天重复 0%

### 发现两个存量问题（非本次引入，已写进 baseline.md）
1. **同类相邻 32.6%（HEAD 同样 32.99%）**：家庭卡 44/148=30%，均匀铺开时同类相邻≈该类占比。
   10-21 就警告过别堆家庭。建议把家庭 tag 拆成 伴侣/父母/子女/宠物。
2. **婚姻线几乎不可完成**：彩礼 L 是 60,000 borrow + 28,000 spend 的自杀选项；
   「体面会算账」画像 1200 局仅 1% 走到添丁，p50 只有 14 天。婚姻线需要重定价。

## 二轮：验收反馈两条（晚间追加）

**反馈 1：滑卡时能看到底下那张卡，但翻上来的却是另一张。**
根因：垫层本来就会预读袋里的下一张，但那个预览天生不可能准——下一张要等这次
选择结算完（day、数值、冷却都变了）才抽得出，还可能被关联卡插队。
修复：垫层改成**空白牌背**（`deckBack()`），只保留「还有牌」的视觉暗示；
`pickPeek()` 删除，`bagFind` 去掉 skip 参数；三件套驱动器同步摘掉 peek。
连带语义修正：垫层不再记 `S.seen`——「看见」只能从真出场的卡记账。

**反馈 2：涨跌做成分时图，涨停/跌停也用分时线表达。**
`tapeHTML()`：昨收=中轴虚线；涨红跌绿 + 渐变面积；封板日线爬到边界压平 +
实心标签「涨停 +10%」；纵轴自适应 3%~10%（到板必 ±10%）；停牌平线灰标签。
路径由 (day, 昨收, 今收, 是否封板) **确定性生成，一个 Math.random 都不调**——
展示层动了随机序列就会挪动抽卡和行情，所有仿真基线失去可比性。

**踩坑**：划线动画第一版用 `pathLength="1"+stroke-dasharray:1` 归一化写法，
浏览器实测线画到 40%~80% 就被截断（量长精度问题）；
换成 `getTotalLength()` 精确设置 dasharray 后恢复（桩环境 try/catch 静默跳过）。

**回归**：校验 148 张全绿 / 伪选择 0% / maximin p50=55 p90=132 ≥60天 47.9%（与基线一致）/
乱滑均 30.9 天 / 同卡相邻 0%、一局重复 0%、单卡最多 1 次。check-repeat 的
「三张牌里有重复」指标随空白牌背作废（输出已改为 N/A 说明）。

## 三轮：行情口径统一（晚间追加）

**反馈：每日提示「这只票涨/跌 X%」和分时图对不上。**
量化：80 局 × 60 天，2027 个可比日，**14.8% 的天符号相反、40.7% 幅度差超 1pp**。

根因（两个口径混用）：
1. 分时图画的是**股票指数**的涨跌 `r`；每日提示写的却是**持仓**涨跌幅 `pct`——
   它带 1.3× 杠杆 × 风险放大（1~3.4x）再叠噪声，小行情日符号直接翻转。
2. **泡沫破日更离谱**：持仓 −44% 的那天，指数照常绘制（泡沫日 drift +2.8pp，多半是红线），
   玩家看到「图是红的、文字喊 −44%」。

修复（纯展示层，`prototype.html`）：
- 「这只票」句改读 `r`，与图同源；持仓与股价差 ≥1.5pp 时单独补「你的仓位赚/亏 X%」
  （把杠杆机制亮给玩家，而不是藏进一个对不上的数）
- 泡沫破：指数同步崩（`S.index *= (1-drop)`，展示专用不影响平衡），分时图新增
  `lim:"crash"`——按实际跌幅撑开纵轴、跌到底压平、绿实心标「崩 −47.2%」；
  已 push 的「这只票」句用 `stockAt` 下标回写，崩盘幅度直接读图用的 `close/prev-1`
- 平盘（|dev|<0.05pp）不再标红「今 +0.0%」，改灰色「今 0.0%」

**回归**：2027 日文字 vs 图 **0 符号相反 0 幅度差**；三件套与基线逐位一致
（maximin p50=55/p90=132/≥60天 47.9%；乱滑 30.9 天；重复率全 0）。规则进 AGENTS.md。

## 四轮：分时线去「太规律」（晚间追加）

**反馈：分时线太规律，想要更多波动/噪音，收盘涨跌对上就行。**
旧实现是「平滑 S 曲线 + ±0.5% 双正弦抖动」，所以每天长得都差不多。

重写 `tapeHTML()` 生成逻辑（依旧纯展示、零平衡影响）：
- **本地 Lehmer 伪随机 `tapeRand(seed)`**：种子只取 day，自己播一串——
  要随机感但绝不碰全局 `Math.random`（那是基线的命根子）
- **AR(1) 自相关噪声**（w = w×0.76 + rnd×0.62）：噪声带记忆，像盘口，不是一秒一跳的白噪声；
  幅度 = band×0.34，跟着当天振幅走（小行情也看得出在晃）
- **每天换一种走势骨架**：五种 hump（平滑 / 低开走高 / 冲高回落 / 深 V / 磨半天再拉）
  按 day 确定，叠在基础路径上
- **每天一根尖刺**（位置由 day 确定，幅度 ≤2.2×amp）：偶尔一根突兀的针
- 两端仍钉死在真实收盘上；封板日噪声压住不许戳破板；崩盘日贴底不越界
- **顺手修**：停牌日的线原来也带抖动（价格冻结却会晃），改 amp=0 死平线

回归：148 张卡全绿 / 伪选择 0% / 重复率全 0 / policy 与基线逐位一致
（maximin p50=55 p90=132 47.9%；乱滑 30.9 天）。

## 五轮：家庭线三项修复 + 婚姻线重新定价（Windows 端，用户拍板后实施）

用户拍板四点：① 彩礼右项用「先不结，再攒攒」② 认真玩 **30% 能结婚、15% 能有孩子**
③ tag 拆成 **伴侣 / 家人 / 孩子 / 宠物 / 房子** ④ 恋爱期窗口「收一下」（上限 100 天）。
方案见 `docs/plan/family-fix.md`，本节记实施与实测。

### 1. 卡池：53 张「家庭」拆成五类（池 148 → 150）

| 新 tag | 张数 | 怎么分 |
|---|---|---|
| 伴侣 | 28 | 女友 13 + 老婆 13 + 新增 2 |
| 孩子 | 12 | 孩子 7 + 老师 3 + 补习班 2 |
| 家人 | 10 | 老妈 6 + 老爸 2 + 丈母娘 3（合计 10，其中老妈含住院/体检/电话） |
| 宠物 | 3 | 猫 |
| 房子 | 2 | 房东 |

卡 id 一律不动（`fam_*` 被几十条 when 引用）；新卡用新前缀（`love_*`）。

### 2. 发现并修掉一个更深的 bug：`no:did:` 被当成「回响卡」

`isChain()` 原来只查 `when` 里有没有 `did:`／`seen:` 字样——把 `no:did:fam_hunli_01`
这种「**还没结婚**」的前置条件也算成了回响，于是三张恋爱入口卡被塞进插队通道：
天天插队、`cap=1`（一局只出一次）、还绕过难度曲线。修法：判之前先把 `no:did:` / `no:seen:`
从字符串里抹掉，剩下的才是真回响。

### 3. 插队节流：三条规则 + 同类冷却（这才是「扎堆」的正解）

- **隔天**：昨天已经插过队 → 今天必须出普通卡（`_lastWasChain`）
- **同类不连**：插队也看 `_lastTag`；全都同类时才让步，不把卡憋过期
- **关键节点优先**：`pri` 字段（目前只有怀孕卡用，`pri:9`）
- **同类冷却**（新增，作用于普通抽卡和插队）：最近 6 张里该分类已有 2 张 → 这张先歇着；
  普通抽卡分三级让步（1 张 / 2 张 / 不管），保证永远能抽出牌

### 4. 踩到的坑：「快过期先出」把没有窗口的卡饿死了

第一版实现是「按 window 上限升序排，没 window 的当 9999 垫底」——结果怀孕、婚后系列
（全部无 window）永远排在最后，只要有别的链卡可出就轮不到它们，**怀孕卡几乎出不来**。
改为「只有真的剩 15 天以内才优先救它」，其余保持袋内顺序。

## 第六轮（10-26 深夜 · Windows 端）：钱到底花到哪去了

试用反馈两条：
> 「我达成了结局上岸，我都不知道为啥能达成这个结局。」
> 「我 37 天了，钱根本花不完啊。能不能触发一些事件让我花钱啊，每个月拿工资，每个月也要还贷款。」

### 0. 先说根因：`did:` 在浏览器里一直是废的

`resolve()` 记的是 `S.did[c._id]`，`pick()` 记的是 `S.seen[c._id]` ——
但 `sync-json-to-prototype.js` **从来没把 id 写进原型**，CARDS 里的卡对象根本没有 `_id` 字段。
于是浏览器里所有选择都记在 `S.did["undefined"]` 这一个键上：

- 任何 `when:"did:fam_hunli_01"` 永远不成立 → 彩礼、婚礼、首付、房贷、怀孕、产后……
  **整条家庭线在玩家手里一次都没出现过**；
- `isChain()` 同理失效，插队通道形同虚设。

仿真一直没暴露，是因为 `tools/sim/engine.js` 会按 json 顺序自己补 `_id`。
这就是「仿真全绿、玩家却看不到内容」的经典漂移，教训写进 AGENTS.md。

**修复**：sync 输出 `id:`；`resolve/pick` 改用 `c.id`；engine 改成逐卡核对 `c.id === j.id`，
原型缺 id 直接抛错（以后忘跑 sync 会当场报，不会再静默失效）。

这条一修，玩家 37 天看不到彩礼/婚礼/首付/房贷的原因就清楚了 —— 也顺带解释了「钱花不完」：
这个游戏里唯三的大额支出（彩礼 12,000、婚礼 12,500、首付 25,000）全在那条链上。

### 1. 月度账本：工资月发 + 房租 + 月供

原来工资 6,500 / 15 天 = 月 13,000，而生活燃烧只有 200/天 ≈ 月 6,000 ——
**日结算净 +143 天**，等于每天白送 143 块，30 天白送 4,300。玩家当然觉得钱花不完。

改成真·月度节奏（每月 5 号）：

| 项 | 数值 | 说明 |
|---|---|---|
| 月薪 | 11,000 | 失业就没了 |
| 房租 | 4,600 起，每月 ×1.10 | 房东年年涨，按月折算 |
| 水电物业通讯保险 | 1,400 起，同上 | |
| 月供 | 欠款 ×12%，最低 700 | 现金不够就滚回负债，心态 −2、社会 −2 |
| 日用 | 80/天（前 20 天）→ 95×1.016^n | 吃饭通勤，压低 |

- 账单现金不够：不卖股票、不静默，**整笔转成负债**并在日志里写明欠了多少。
- 日结算从 **+143/天 → −17/天**（maximin 实测），净值曲线终于往下走。
- 现金不再允许是负数：负的部分当场转进负债条（看得见才叫负债）。

HUD 加了常驻胶囊：`🏠 3 天后交房租 ¥6,000`，点开说明「每月 5 号工资进来、当天扣掉」。

### 2. 上岸改成玩家自己决定

原来是 `check()` 里一行 if：空仓 + 无债 + 净值 30,000 → 立刻结束。
玩家卖完最后一点股票、还完最后一笔钱，游戏突然就完了，完全不知道发生了什么。

现在：条件满足只是「可以走了」，会来一张 **urgent 卡**（`self_exit_01`，
不走袋子、不进分批，条件满足就插队，隔两天再问，一局最多 4 次）：

- 「再玩两天」→ 继续，代价是风险 +6
- 「收手，删掉 App」→ 触发上岸结局

结局面板开头统一加了「**为什么是这个结局：**」，上岸那条会写清
「这是你自己按下的停止键：仓位清空、欠款还清，手里还剩 ¥31,200（起步 20,000，收益 +56%）」。

### 3. 首付卡：借了钱要真的花出去

`fam_shoufu_01` 原来只有 `borrow:25000`，借来的钱直接躺在现金里 ——
**现金凭空多两万五**，这就是「钱花不完」最直接的来源之一。
改成 `borrow:25000 + spend:25000`（apply 顺序里 borrow 在 spend 前，付得出来），
净值不变、负债 +25,000、现金不涨。

`fam_mortgage_01` 原来是每月来一张「房贷 3,500」的卡，跟新的自动月供重复扣款，
改成一次性通知（cap 1）：「房贷批了。以后每月 5 号，自动扣 3,000。」

### 4. 八张花钱卡

手机屏碎 1,200 / 牙疼 3,000 / 眼镜断了 1,800 / 空调坏 2,400 /

## 第七轮（10-26 深夜 · Windows 端）：每天的金钱变化，飘在脸上

反馈：
> 「我希望加一个每日金钱加和减的数值变化效果在金钱这一栏，这样能直观的看出来我每天的金钱变化，不然每次我金钱有变动看起来不明显。」

### 做法

每天结算完（卡片 + 行情 + 工资 + 账单全部落定），净值旁边飘一个 ±金额，
涨红跌绿（A 股习惯），净值数字本身同时闪一下同色，1.3 秒后淡出：
后面跟一笔小字，告诉你今天最大的那笔钱是从哪来 / 到哪去
（`工资+11,000 等4笔` / `股票−7,000 等3笔` 这种）。

关键取舍：

- **飘的是「净值」不是「现金」**：月供、还钱是现金换负债，净值不动——
  如果飘现金，玩家会看到"还了 3,000 却显示 −3,000"，跟头顶总分对不上。
- **逐笔记账（tick 里 addFlow）+ 「其他」兜底**：工资/房租/日用/利息/股票/泡沫破/强平/奶粉钱
  各记各的，最后差额补一条「其他」，保证明细加起来一定等于头顶那个数——
  账平了玩家才信你，账不平玩家会当场拿计算器对。
- **明细只放一笔**：344px 的手机框里，净值 + 金额 + 收益率已经挤了，
  两笔来源会把「等N笔」截成残废（第一版截图实测），一笔 + 等N笔 刚好。
- **绝对定位、不占布局**：不然每天数字一变，右边收益率的位置就抖一下。
- **没变化就不飘、不播动画**：重开/教程/结局面板都不留旧数字在 DOM 里。

### 新增断言（tools/smoke-ui.js +4 项 → 13 项全绿）

涨飘红且金额=净值差 · 跌飘绿 · 没变化不重播 · 发薪日飘字总数=实际净值变化且点出工资。
另外用 Chrome headless 截图目检了两轮：第一版明细两行压住了资金条、第二版明细被
收益率盖住，都靠截图抓出来改掉——桩 DOM 测不出重叠，截图能。

仿真基线不动（结局分布逐位一致——这个功能纯展示，不碰任何数值）。

### 修订（同夜 · 用户反馈）

> 「后面跟的小字不要，很奇怪。然后文字浮现后停留的时间可以稍微久一些。」

- 来源明细整个拆掉（flowItems / addFlow / _cardNet / _flow 全删，不留死代码），
  只留 ±金额。钱从哪来底部日志本来就有，不缺这一行。
- 动画 1.3s → 2.9s：前 0.2s 淡入，中间停 2.2s，最后 0.5s 淡出——
  玩家读完牌抬起眼还能看见这笔账。
- 截图复核三个时间点（0.3s / 1.8s / 2.7s）：1.8s 仍清晰可见（旧版已消失）、2.7s 进入淡出。
- smoke-ui 断言同步收紧：飘字文本必须严格是「±¥金额」，有多余字符直接失败。
