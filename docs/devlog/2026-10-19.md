## 追加：扫描潜伏的旧版残留

合并提交后用户提醒："昨天发给 Windows 上 AI 的那份 `prototype.html` 不是最新的，
Mac 上修改过后的 HTML 才是现在开发的最新版。"

这句话直接坐实了上一段「真冲突」的根因：Windows 那晚抽取 `cards.json` 时用的
就是这份旧 prototype。但**只重抽 `cards.json` 不够**——`docs/` 和 `spike/`
里凡是手抄过卡牌文案的硬编码副本，都可能带着旧值。

扫描方法（防御性，把"出 N"形式的所有文本都过一遍）：

```bash
# 1. 找旧值 4,200
grep -rn "4,200" --include="*.md" --include="*.js" --include="*.json" . | grep -v devlog
# 2. 列出 prototype 当前所有 "出 N" 形式做 ground truth
grep -oE 's:"出 [^"]+"' prototype.html | sort -u
```

结果找到 2 处真冲突（已修复，commit 待发）：

| 位置 | 旧值 | 新值 |
|---|---|---|
| `docs/design/game-design.md:138` | "出 4,200" | "出 5,500" |
| `spike/wxs-swipe/pages/swipe/index.js:14` | `'出 4,200'` | `'出 5,500'` |

都是「老婆/房贷」这一张卡的 R 文本。`docs/` 那处是说明性示例，spike 那处是
卡面抄录——两处都是手抄时跟的是旧 prototype（10-16 定标前），定标后没人回去更新。

**为什么这件事值得单独记**：重抽 `cards.json` 只能修复**结构化派生**，
**手抄副本**（文档示例、spike 卡面、可能的 README 引用）必须靠 grep 扫。
本质上 `docs/` 和 `spike/` 里有 v3 卡面文案的每一行都可能是"潜伏的旧版"，
没人提醒就漏。

**对应的工程教训**：

1. **派生数据有三种**：
   - 自动派生（`cards.json`）→ 重跑脚本就行
   - 文档示例（`game-design.md` 里的卡牌结构）→ 写文档的人手工同步，易漏
   - 跨语言抄录（spike 的 WXML/WXSS/JS 里的卡面文案）→ 跨栈最容易漂移
2. **三类都需要不同的同步机制**：
   - 自动：把重抽写进 CI 或加 source hash 校验
   - 文档：每改一次 prototype，至少 grep 一次
   - 跨栈：要么用同一份数据源（推荐），要么不抄——把"卡面来源"明确指向 prototype

这条以后给 `AGENTS.md` 加一条「卡面与数值改动后必跑 grep」是值得的。

## 卡池真源反转 + 触发条件声明式化（下午补充）

上一节记的「派生数据漂移」教训，这次从根上修了：**不再让 prototype 当真源**。

### 为什么必须反转

用户提出「想要一个配置文件/表格，能明显看到所有卡片的数值变化，方便后期自己改」。
这个诉求本身就要求配置能被人直接编辑 —— 而配置如果是从 prototype **抽取**出来的派生物，
人改了它也不会回流到代码，改了等于白改。所以只能反转。

反转前：`prototype.html`（硬编码 CARDS）→ 抽取 → `cards.json`
反转后：`data/cards.json`（真源）→ `sync-json-to-prototype.js` → `prototype.html`

### 第一个障碍：when 是 JS 函数，写不进表格

26 张卡的触发条件原本是 `function(){return S.mind<30;}` 这种函数字符串。
函数无法在表格里编辑，也无法序列化 —— 这恰好违反 `AGENTS.md` 里早就写着的一条规则
（「触发条件用声明式描述，不要用 function」），说明那条规则之前一直没落地。

设计了一个表格友好的 DSL：

| 写法 | 含义 |
|---|---|
| `no:baby` / `has:fired` | 无 / 有某状态 |
| `mind<30`、`social>52`、`equity>800` | 属性比较 |
| `equity>cost` | 浮盈（相对成本） |
| `equity<cost*0.85` | 跌超 15% |
| `;` | 且（AND） |
| `\|` | 或（OR） |

26 处全部迁移。**做了新旧逻辑对拍：随机生成 3000 组游戏状态 × 26 张卡 = 78000 次判定对比，
零不一致**，确认重构 100% 等价。这一步是必要的 —— 「看起来对」和「真的等价」是两回事，
平衡数据一旦悄悄变了，后面所有调优都建立在错误地基上。

### 踩到的坑：`CARDS = [` 是 `CARDS = []` 的前缀子串

同步脚本定位 CARDS 数组时用了 `html.indexOf('CARDS = [')`。
而文件开头的变量声明是 `var S, ..., CARDS = [], ST = {};` —— `CARDS = []` 里
**包含子串 `CARDS = [`**，于是匹配到了声明处，替换范围一路吞掉到数组结尾之间的
**所有函数定义**，整个 prototype 被写空一次。

两个处理：
1. 锚点改成带前导换行的 `'\nCARDS = ['`（这才是真正的数组赋值行）
2. 加**落盘前安全检查**：替换后必须仍能找到 `whenOK / tick / resolve / apply / reset` 五个函数，
   少一个就中止、不写文件

从备份恢复后重跑，ROUND-TRIP 无损、仿真平衡与基线一致（随机 17.3% / 会玩 32.2%）。

类似的前缀/子串误匹配，在「按文本锚点改写代码」这类脚本里是通用陷阱，值得记牢。

### 工具链

| 文件 | 作用 | 说明 |
|---|---|---|
| `tools/build-manager.js` | 生成网页管理表 | 顺带产出 `data/cards-flat.json`；内置**往返自检**（63 张卡逐张深比较，键顺序不计） |
| `tools/cards-manager.html` | 网页可视化管理表 | 63 行 × 31 列，可筛选/排序/编辑/导出 JSON |
| `tools/export-xlsx.py` | 导出 Excel | 63×31，含「填表说明」页，分类列带下拉 |
| `tools/sync-json-to-prototype.js` | json → prototype | 带安全检查 |

管理表为什么是「生成」的而不是静态页：浏览器在 `file://` 下用 fetch 读本地 JSON
会被 CORS 拦。所以把当前卡池**内嵌**进页面里，双击打开即可编辑，改完导出下载。

转换逻辑（flat/unflat）只在 `build-manager.js` 里写一份，再用 `toString()` 注入进
生成的 HTML —— 避免「Node 端和浏览器端各写一遍、慢慢漂移」。

**这一轮最值得记的一个算术**：

一局 = 60 天 × 3 张 = 180 抽；选卡逻辑是 `c._used < 2`，即每张卡单局最多 2 次。
所以 `63 × 2 = 126 < 180` —— 池子在一局内必被抽空并清零重来，
**平均每张卡一局出现 2.9 次**。

之前一直把问题描述成「卡不够多」，其实是**连一局不重复都做不到**。
这个数直接决定了扩容目标：≥180 才可能一局不重复，≥260 才能跨 3 局不明显重复。
Reigns 是 750，但它是多君主 + 多轮继承堆出来的，不能直接对标。

**顺手修正了一个旧数字**：之前说「63 张里 18 张支配选项，29%」。
换成分母更干净的口径重算（只统计纯数值、不含买卖借还的 30 张可比卡，且按正确符号方向判）：
**14/30 = 47%**。两个口径分母不同、不能互相校正，但结论一致且新数字更难看。
教训：支配选项检测里，`spend` 是负向、`risk` 是负向，符号写错就会系统性漏判；
买卖借还这类「当下不可比」的效果应该排除，而不是当成零。
