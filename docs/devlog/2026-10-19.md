## 备注

今天确认了两件事对项目的长期价值：

1. **「不要先导代码」这条规矩的本质是「先验证技术选型，再迁移业务逻辑」**。
   WXS 手感是迁移路径上的最大未知数（touchmove 在 WXS 里能不能不丢帧、能不能
   跟手，模拟器回答不了）。如果一上手就把 prototype 拷进 `pages/`，就会面临
   「是 prototype 的问题还是 WXS 的问题」这种二义性诊断。先用 spike 隔离验证，
   至少能分清是引擎层还是业务层。
2. **「同一份文件不要两边同时改」比「哪台机器是主源」更有约束力**。
   这次 Mac 端唯一做的就是 `HANDOFF.md` 一份文件，Windows 端 pull 不会看到任何
   prototype 相关 diff。零冲突面。哪天 prototype 进仓库了也按这个原则做：
   谁在改就先 push，接到通知的人不要碰那个文件。

## 经验值

Mac 上 git 全局配置在 `~/.gitconfig`，跟 Windows 上的 `C:\Users\ZhuanZ\.gitconfig`
分别管理。两端姓名邮箱要一致，**提交作者名一旦不同步，git log 就会把同一个人
显示成两个角色**，以后追责时一脸懵。
