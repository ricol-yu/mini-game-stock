### 做了什么

1. **id 语义化**：63 张卡全部从 `c001` 迁到 `fam_mortgage_01` 式语义 id。
   迁移脚本用显式映射表而非自动规则——id 一旦定下永不改，自动生成的东西没法人工审查。
   顺带把 `whoId` 全量写入（N4 素材 manifest 的锚点）。
   **验证**：`sync-json-to-prototype.js` 后 prototype.html 零 diff（CARDS 块 8780→8780 字节）——
   id 本来就不进原型，迁移对游戏零影响。

2. **schema v2**：`window`/`weight`/`once`/`hidden` 缺省不落盘（保持真源 JSON 形状干净）。
   DSL 三个谓词 `did:/seen:/pick:` 只进校验器不进引擎——**这是今晚最重要的一个克制**：
   现在实装就会改变选卡行为，基线就不再是"当前游戏"的基线了。

3. **校验器**：8 类检查。`--selftest` 注入 9 个坏样例全部拦截、真实数据零误报。
   校验函数写成自包含纯函数，`build-manager.js` 用 `toString()` 注入管理表——
   CLI 和网页跑的是同一份逻辑，不会各写一遍慢慢漂移。

4. **仿真器**：架构上否掉了计划里"移植成 Node 版"的写法，改为**把 prototype.html
   的真实脚本装进 vm 沙箱**（DOM 桩吸收渲染、种子注入 `Math.random`）。
   移植 = 两份逻辑必然漂移；直接跑原型自己的代码，对拍在架构层面成立。
   等价性工作只有一处：when 字符串解析太慢，写了快版过滤器，并做 10,400 组
   状态×卡对拍强制验证，100% 一致才允许开跑。

5. **基线**：10 万局 · seed=20261020 · 99.8s。结局分布、重复率、卡覆盖率全部落档

6. **管理表升级**：+5 列（whoId/window/weight/once/hidden）、新增/复制卡（id 自动顺延）、

### 今晚踩的坑（值得记）

- **vm 沙箱不是免费的**：把主循环整体搬进沙箱执行反而比 Node 侧慢一倍
  （10k 局 22.5s vs 10.7s）。这个环境的 vm 上下文执行开销高。最终架构：
  主循环留 Node 侧，只有 resolve/tick/check 三个真实函数跨边界。
  三种架构跑出**逐位一致**的结果（34.37%/3437 局分毫不差），确定性反证了正确性。
- `sandbox.Math` 在沙箱对象上摸不到（contextify 的内建不反透），注入 RNG 要从上下文内部改。
- `money()` 的返回值在 tick 里会被 `.replace()`——桩必须返回字符串，不能偷懒返回数字。
- 纯显示函数（render/money）可以安全置空提速：不消耗随机数、不改状态，
  置空后结局分布逐位不变（回归验证过）。
