# 2026-10-28

## 第十轮（Windows 端）：滑动提示只报价 + 一次还不上就是老赖

> 用户反馈：①「先欠着」这类预警文案很怪，滑动提示只报要花多少钱，借款的事弹提示再说；
> ② 第一次还款还不上就该成老赖，不是攒三次；③ 老赖是 debuff（降社会和心态），
> 直到下一次把债还清才解除。

### 1. 滑动提示（shortNote）重写：只报价格

- 花钱项（spend）→ 「花 ¥X」；买入项（buy）→ 「买 ¥X」（上头状态 1.35 倍照算）；
  纯扣现金（cash<0）也标「花 ¥X」。
- 「差 X 会欠着」「现金只够买 X」整套删掉——后果是结算弹提示的事（「💸 现金不够，欠下 ¥X」
  本来就有），选之前报价钱、选之后报后果，各管各的。

### 2. 老赖规则改狠：一次还不上就上名单

- 原来：还大半记 1 笔 / 不到六成记 2 笔，攒满 LAOLAI_AT=3 上名单。
- 现在：月供只要没全额还上（哪怕还了九成），**一次就上失信名单**，三档记账合并成一档。
- LAOLAI_AT 常量删除；S.arrears 只留作后台统计，HUD 的「⚠️ 逾期 N/3」胶囊删除
  （成没成老赖看红标就够）。
- 解除条件不变：**把债还清（debt≤1）才解除**，每天心态 −1.2、社会 −0.2，
  发薪日工资划扣 25%，借钱减半——全是既有逻辑。
- 全额还上当期节点 → arrears 归零（记录翻篇），但老赖状态不因此解除。

### 3. 实测数据（diag-debt，各 1500 局）

| 策略 | 成过老赖 | 挂的天数 p90 |
|---|---|---|
| 会玩·maximin | 36.9% | 11 天 |
| 只花钱不还钱 | 25.1% | 6 天 |
| 会玩·爱借钱 | 12.3% | 1 天 |
| 随机 | 14.1% | 3 天 |

认真玩约 1/3 的局会短暂成老赖、多数几天内还清——比攒三次狠得多，先按用户拍板收着，
嫌太疼再谈「小额欠款豁免」之类的缓冲。

### 4. 测试与检查

- smoke-ui 更新 3 处：滑动提示只报价（花/买），一次没还上→直接上名单，
  还大半没还满→一样上名单（用结算文案里的「只凑出」区分「还了部分」和「一分没还」）。
  31+2=33 项全绿。validate / simulate / policy / dominance / repeat 全过。
- 技巧回报 x11.59，maximin 通关 78.8%。

## 第二轮：金额融进选项文案（删掉「花 ¥X」小字）

> 用户反馈：「买 ¥X」小字还是很怪——「转一半补仓」就该写成「转一半 4,800 补仓」，
> 「全借」就该写成「5,000 全借」。

- 卡面 label 引入 `{}` 金额占位符（120 处带金额的选项全部改写，一次性脚本
  `tools/merge-amount-labels.py`），原型新增 `labelOf()` 渲染时填真实数字。
- **为什么用占位符而不是写死数字**：买入在「上头」状态要多掏 35%，写死必错；
  占位符保证融进话里的金额永远是真实扣的数。以后调金额也不用同步改文案。
- 顺手把原来 25 张「文案里已有死数字」的卡也换成占位符（上车 3,000 → 上车 {}）。
- `shortNote` 整个删除；validate 新规则：**带金额的选项必须有 {}、写了 {} 必须有金额**，
  文案长度按渲染后宽度计（{} 算 5 字，上限 18）。
- 冒烟测试更新：{} 填数字、没金额的一侧不带数字、上头状态买入 3,000 显示 4,050。
- Playwright + 系统 Chrome 实机截图目检 3 张正式卡：金额融进句子、无溢出错行。

## 第四轮：素材规范瘦身（v2）+ 卡面人物位落地

> 用户反馈：v1 素材清单太重（小程序扛不住），一个人物一套 + 基础 UI 就够；
> 素材规格要按移动端来；素材位置要给占位，人物图太大文字会放不下。

**实测先行（Playwright 三档机型）**：卡面内宽 274 逻辑px，文字最多两行 = 55px，
文字区本来就有 ~200px 是空的——卡面缺的不是空间，是没人去用。v1 的 750×1000
整屏立绘根本塞不进卡面，240×240 头像显示位只有 31px，全按「大图思维」想错了。

- **卡面人物位落地**：`.card .art` 插在 who 和文字之间，出血到卡边；
  铁律 **文字优先**——`.txt` 改自然高度、`.art` 吃剩余空间，文字变长图自动缩
  （实测 4 行文字图从 200 缩到 145，永远不溢出，320 小屏同样成立）。
- **占位机制**：素材没到位显示角色 emoji（放大 + 渐变底），版式与有图态一致；
  `ART_ON` 开关（默认关，不发明知 404 的请求）或 `?art=1` 预览，单图 404 自动塌回占位。
- **表情差分改整图换脸**：卡数据加可选 `emo` 字段 → 加载 `<whoId>_<emo>.png`，
  美术在同一 PSD 换表情导出天然对齐；放弃了贴片锚点方案（128px 贴片放 140px 脸区会糊，
  像素级对齐对个人开发不现实）。老婆 4 张卡已标 emo 做演示链路。
- **规范 v2**：84+ 张 → 完全体 26 张（第一批 11 个 ≈ 500KB）；
  人物图 640×400（显示 308×200，@3x 不值得）、脸锚点 (50%,30%)、安全区左右 4% 底 5%；
  必须 WebP(透明) 或 PNG-8（PNG-24 一张 100KB+ 直接爆 2MB 主包）；
  情境卡 30 张场景图砍成「emoji 占位 / 可选 3 张」，结局插图 11 张砍成 2–3 张。
- 用 canvas 生成规格测试图实机截图验证：底图、差分（angry 版正确命中）、占位三态全过。
- sync 脚本输出加 `wid`（=whoId，素材路径零映射表）与 `emo` 字段。

## 第五轮：王权式 HUD + 人物位加大 + 教程精简

> 用户贴了《王权》(Reigns) 截图：四个命值做成一行填充图标、屏幕大头给画面、
> 文案只占一小段。要求照此改造。

- **HUD 四条命王权化**：四行「label+进度条+数值」压成一行四个 SVG 图标
  （闪电=精力 / 心=心态 / 三角叹号=风险 / 双人=社会）。图标形状当 clipPath，
  矩形从底往上填，填多少=数值多少：满格实心、空了只剩轮廓。数值挪进悬停 tip
  （信息没丢，不常驻）；告警逻辑不变（低值红填充+闪烁）。
- **卡面人物位加大**：HUD 省下 ~58px，图区 200 → 233px 高、308×200 扁宽改
  274×233 近方（王权式圆角内嵌，不再出血贴边）。文字优先铁律不变：
  实测 4 行文字图缩到 178 仍不溢出。素材规格随之 640×400 → **640×540**。
- **教程精简**：三张序幕卡文案 76/69/160 字 → 37/34/32 字（要点挪进
  HUD 图标 tip 和还款胶囊 tip，不用一次倒给玩家）；TUT 卡预留素材名 tut_night/
  tut_you/tut_market（第三批），中间大块占位先顶上。
- 截图目检三态（序幕卡/正式卡/图标 tip）全过；smoke-ui 31 项全绿。

## 第六轮：删 who 行 + 选项印章王权化

> 用户反馈：① 卡顶「谁在说话」那行（头像+名字+tag）不需要，没必要告诉玩家；
> ② 底部常驻的左右滑提示改成滑动时才显示，参考王权。

- **删 .who 行**：说话人从卡面消失（读内容就知道是谁），who/tag 字段数据保留。
- **选项不常驻**：底部 .foot（左右选项）和 .tips（常驻操作说明）整个删掉；
  拖动时对应侧的「选项印章」浮现（stamp 机制原本就有，只是把填文字从 fly 提前到
  pointermove）：拖左亮左选项（绿）、拖右亮右选项（红），透明度跟拖动距离走，
  出牌瞬间定格随卡飞出。静止卡面 = 画面 + 文案，跟王权一致。
- 两个坑：① stamp 是 absolute 且 DOM 在 .art 前面，被人物位盖住——补 z-index:5；
  印章贴边 13px，拖动时先出屏——挪到 22% 靠中央。截图左右两向验证通过。
- **图区再次变大**：274×233 → **274×325 竖版**（0.84:1），素材规格 640×540 →
  **560×640（7:8）**，体积预算不变（≤45KB/张）。文字优先不变（4 行文字仍不溢出）。
- 冒烟断言更新：「金额融进文案」改为直接验证 labelOf() + 印章结构 + 静止卡面不含选项文字。
