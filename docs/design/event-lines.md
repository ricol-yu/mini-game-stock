# 事件线设计（N3 关联卡）

> 起因：用户反馈「事件出现得太突然——比如突然就被裁员了。最好和我前面的决策有关联：
> 经常工作时看盘、加班不去、团建不去，最后导致被裁员。先做一个大的事件线，然后往里填充。」
>
> 本文是五条事件线的总图。职场线已实装（2026-10-21），其余四线留骨架待填充。

## 1. 机制：三件工具

| 工具 | 语法 | 语义 |
|---|---|---|
| **did:（记账）** | `did:cardid.l` / `did:cardid.r` / `did:cardid` | 那张卡的左/右选项你选过。**最后一次选择生效**，同一张卡可以反复出，翻案会覆盖旧账 |
| **seen:（伏笔）** | `seen:cardid` | 那张卡出现过（含叠在下面的垫层牌）——「你见过它，哪怕没理它」 |
| **window:（时机）** | `"window": [起, 止]` | 第几天到第几天之间才可能出场。时机没到，卡在袋里躺着 |

组合语法不变：`;`/`&` = 且，`|` = 或，**没有括号**——「A 且（B 或 C）」要展开成
`A;B|A;C`。写长了没关系，校验器会查引用的卡是否存在。

记录位置：`resolve()` 记 did（打出才记），`pick()`/`pickPeek()` 记 seen（看见就记）。
都在 `S.did` / `S.seen`，一局重开即清零。

## 2. 五条线总图

结构统一为三层：**触发层**（日常小选择，可反复出）→ **递进层**（记账后的回响）
→ **清算层**（不可逆的大事，接状态或结局）。

### 2.1 职场线 ✅ 已实装（裁员链）

```
触发层 day 4-42（失业后不再出）
  work_screen_01   项目明早上线，你在改自己的止损位
  work_bossmeet_01 例会走神被点名
  work_overtime_01 通宵上线，你走吗
  work_tuanjian_01 团建火锅局（新增）
        │ did:.l 记账（改完再说 / 承认走神 / 准时走 / 不去）
        ▼
递进层
  work_raise_01  调薪名单没有你     day 18-50  条件：任一 miss
  work_review_01 HR 找你聊下半年规划  day 22-54  条件：调薪卡你忍了(.l)
  work_layoff_01 优化名单下周公布     day 28-55  条件：忍了调薪 + 再 miss 一笔
        │
        ▼
清算层（选择分流）
  work_layoff_02 名单公布，没有你        day 30-58  条件：预警卡选了「主动揽活」(.l) → 保住
  work_fired_01  HR 请你收拾工位 📦失业  day 30-58  条件：预警卡选了「装没听见」(.r) → 被裁
  work_jobhunt_01 / work_offer_01      条件：has:fired（原有）
```

设计取舍：**裁员不可逆但可避免**。一次 miss 只是记账，忍了调薪 + 再 miss 才进名单。
到了预警卡，选择才真正分流：主动揽活（心态 -6 + 风险 +3）保住工作；
装没听见继续盯盘（加仓 4000）则 HR 必来。
没有分支回退——被裁线仍是单行道。
正向分支（连续专心 → 升职/加薪卡）是下一批的内容，见 §4。

> 2026-10-21 修正：预警卡原选项「陪家人 / 加仓」与文案脱节（玩家指出不合理），
> 已改为「主动揽活 / 装没听见」，且选择决定是否被裁（原来见过预警必被裁，选择无意义）。

```

        → fam_hospital_01（爸住院垫 6,500，大额清算）

        → fam_inlaws_01（借 20,000，大额清算）
```

设计点：父母线的触发层应该记「**回电话/不回**」的账——`did:fam_momcall_01.l`（嗯嗯两声挂了）
攒多了，医院卡才轮得到你垫钱时良心疼。清算卡用 `seen:` 铺垫（体检单出现过）。

### 2.4 子女线（骨架，素材最全，7 张，部分已用 has:baby 串起）

```
fam_pregnant_01（怀孕 → 👶状态）→ fam_prenatal_01 / fam_fever_01 / fam_babysfirst_01（has:baby）
→ fam_child_01（你为什么总在看手机）→ fam_parentmeet_01（家长会）→ fam_teacher_01（上课走神）
→ fam_reportcard_01（举着卷子）→ fam_kidsfee_01（兴趣班 6,800）
```

设计点：这条线的账应该是「**陪/不陪**」二选一贯穿——每张卡 L 或 R 记同一方向的账，
攒够后在 fam_reportcard_01 / fam_teacher_01 清算（孩子的成绩/性格跟着你的选择走）。

### 2.5 宠物线（骨架，素材 1 张，缺得最多）

```
acc_cat_01（猫踩键盘帮你下单 —— 纯意外卡，先不接账）
```

待补 3-4 张：领养/捡猫（触发，给心态回血的小卡）→ 疫苗/猫粮（小额 spend 触发）→
猫生病（清算：兽医 3,000-5,000，mind 大额代价）。宠物线的功能定位是**心态储蓄罐**：
它只给心态和社交回血、只在生病时要钱——让「不敢花钱的人」也有花钱的理由。

## 3. 工程注意事项

- **链卡别删触发层的 miss 侧**：触发层四张卡的 L 选项是记账来源，改选项前先看本文件。
- **清算卡的 window 上限给到 58**：60 天必结算，留 2 天余量给「出现但没被抽到」。
- **did 是最后选择生效**：同一张触发卡二次出现、玩家换边，旧账被覆盖——写递进条件时按
  「最后一次怎么选的」理解。
- **链卡 tag 保持原类**（职场卡的清算层还是职场）：洗牌袋按 tag 分层，改 tag 会改变出场密度。
- **验证链路是否真的会触发**：`node tools/check-chain.js`（待写）——批量跑局统计
  work_fired_01 出场率与 did 记账命中率。当前用 simulate.js 的卡覆盖表近似验证。
