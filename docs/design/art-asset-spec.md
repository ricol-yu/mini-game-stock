# 美术素材规范 v3 · 人物 + 场景两层合成

> 2026-11-03 第三版。v2 的「一人一张图」在 165 张卡 / 57 个 whoId 面前出不完（v2 全量要 84+ 张），
> 且用户已明确卡面要「人物 + 场景」的画面感。v3 把素材拆成两层：
> **场景底图（按 tag，10 张）+ 人物抠图（按角色，13 个）**，在卡面图位里合成。
> 目标：**10 张场景先把 165 张卡的门面全部撑起来**，人物按出场频次分批补齐。
> 本文所有频次数字均由 `node` 直接统计 `data/cards.json`（2026-11-03，165 张）得出，不是估算。

## 0. 结论速查

| 问题 | 结论 |
|---|---|
| 合成模型 | 两层：场景底（tag 级）× 人物抠图（角色级），合成发生在卡面图位，前端只叠两层静态图 |
| 场景张数 | **10 张**（9 张直接命中全部 165 卡，1 张兜底/结局用） |
| 角色数量 | **13 个**；现有只有 laopo（32 卡 = 19.4%） |
| 差分数量 | **只要 4 个，且全在 laopo 上**（数据里 `emo` 仅 laopo 有值，其他角色 0 个） |
| 165 卡画面覆盖 | 100% 有场景；**85 卡有专属/复用人物**（51.5%）、**13 卡剪影**（7.9%）、**56 卡无人场景 + 物件焦点位**（33.9%）、**11 卡纯空镜**（6.7%）——后两类是设计，不是欠账 |
| 导出 | 场景 **640×720** WebP q80；人物 **640×720 带透明** WebP q80；同一套画布坐标 |
| 命名 | `assets/bg/scene_<key>.webp`、`assets/char/<whoId>[_<emo>].webp`、`assets/char/_sil_single.webp` |
| 查表 | `data/art.json`：tag→场景 / roster / 复用 / 剪影 / 逐卡覆盖 |
| 完全体包体 | **≈1.34MB**（不含音频；音频走分包） |
| 第一批 | 10 场景 + 2 剪影 ≈ **470KB**，上线即 **165/165 卡有完整画面** |

> ⚠️ **实测前提（先看这条再排期）**
> 现有的 `assets/char/laopo*.webp` 5 张是 **560×640、无透明通道（VP8X 无 ALPH）**，
> `assets/char/raw/*.png` 5 张源图也全是 **PNG colorType=2（无 alpha）**。
> 也就是说现有「人物图」是**整幅插画**，不是抠图——直接叠到场景上会糊掉一整块矩形。
> v3 的两层模型要求人物**必须带 alpha**；laopo 重出排进批次 2，重出前用 §3.4 的 flat 模式过渡（不塌版）。

## 1. 两层合成模型

### 1.1 统一画布与显示尺寸

| 项 | 值 | 说明 |
|---|---|---|
| 画布（场景与人物共用） | **640×720**（8:9） | 两层用同一坐标，合成时不需要逐场景调人物位置——这是本方案能量产的关键 |
| 卡面显示尺寸 | **309×350**（390 基准机，见 `design/ui-v2-spec.md §2.1`） | 换算系数 0.483 |
| 显示 / 画布比例 | 309/350 = 0.883 ｜ 640/720 = 0.889 | 差 0.7%，`object-fit:cover` 的实际裁切 **<1%**，可忽略 |
| 分辨率倍数 | 640/309 = **2.07x** | 满足 @2x 屏；Pro Max（430 档，图区宽仍 309）同样够 |
| 320 档（图区 96~135 高） | 同一张图 `cover` 裁切，主裁下沿 | 脸在 28% 高度，永远在安全区，见 §1.3 |

> 导出尺寸与 `ui-v2-spec §5.1` 一致（640×720），不再有 v2 的 560×640 一档。

### 1.2 图层顺序（自下而上）

```
① 场景底图    .u2-art-scene    assets/bg/scene_<key>.webp     cover，铺满
② 调色层      .u2-art-shade    纯 CSS 渐变（不占包体）        统一明度/暖光收口
③ 地面影      .u2-art-ground   纯 CSS 径向渐变                 人物"站"在场景里
④ 人物抠图    .u2-art-person   assets/char/<whoId>_<emo>.webp  带 alpha，底边对齐
⑤ 道具层      .u2-art-prop     (可选) assets/prop/<key>.webp   仅无人物卡，落在焦点位
⑥ 印章 / 正文  .stamp / .txt    —                              永远在最上
```
- 前端只做「两层 `<image>` + 两个 CSS 渐变 div」的叠加，**不需要 canvas、不需要运行时抠图**。
- 小程序 `mode="aspectFill"`（对应 cover），人物层 `mode="aspectFit"` 但**底边对齐**：
  用容器 `align-items:flex-end` + `image` 高度 100% 即可实现「脚踩在基准线」。
- z-index：场景 1 / 调色 2 / 地面影 3 / 人物 4 / 道具 4 / 印章 5。

### 1.3 人物锚点与缩放（画布坐标 → 显示坐标）

| 锚点 | 画布 640×720 | 显示 309×350 | 规则 |
|---|---|---|---|
| 头顶 | y = 118 | y = 57 | 顶部留 16% 给场景（房间/天空），人物不许顶到图区上沿 |
| **脚底基准线** | **y = 678** | **y = 330** | 距图区下沿 20px；所有角色共用，保证不同角色同场不"浮空" |
| 人物高度 | **560px（77.8%）** | 271px | 全身角色按此；半身角色（如老板坐姿）**头顶同样在 118**，脚部可为裁切 |
| **脸中心** | **(320, 202)** | **(154.5, 98) ≈ (50%, 28%)** | 沿用 v2 的 28% 规则，改为像素坐标，不再模糊表述 |
| 脸宽 | 140px（图宽 21.9%） | 68px | 差分对齐基准线 |
| 水平容差 | 中心 ±16px | ±8px | 允许构图微偏，但脸中心必须落在 x ∈ [304, 336] |
| 人物最大宽度 | 400px | 193px | 超出会在 309 显示宽下裁到手臂，构图要留边 |

> **底部让位规则（取代 v2 的「底部 8% 会被裁」）**：脚底基准线固定 678，图区变矮时**从下往上**裁，
> 极端让位（大字号 → 图区 96 高）时可见区域是 y ∈ [0, 430]，即**只保留上半身（脸 + 肩 + 胸）**，
> 脸仍在 28% 高度附近——所以画师把「脸 + 上半身」画扎实就够，腿被裁不影响任何机型。

### 1.4 光线与色调统一（拼不同场景不违和的关键）

**场景侧（出图时就画进去，前端不做任何调色）**
- 三区明度：顶部 18% 区域 L≈82%、中部 L≈58%、地面下 20% 区域 **L≈34%**（地面必须压暗，人物才立得住）。
- 主光方向：**左上 45°，色温 3200K（暖）**；补光：右下，5600K（冷），强度约主光 25%。
- 饱和度上限 **62%**；最亮不超过 L=88%，最暗不低于 L=12%（给 CSS 压暗层和卡面正文留余量）。
- 景深**画在图里**（背景虚化靠笔触/模糊绘制），前端禁止 `filter: blur`（WXSS 支持差、低端机掉帧）。

**人物侧（统一打光，适配任何场景）**
- 人物按「正面 45° 柔光」中性光绘制，**不预烘场景色**（不带橙色氛围光）。
- 右侧边缘 **2px 暖轮廓光 #ffd9a0（60% 不透明）**、左侧 **1px 冷反光 #9fc8e8（35%）**——这两笔是"人在场景里"的胶水。
- 人物整体比场景中区亮 **8~12 L 点**（主角要跳出来）。

**合成侧（CSS，两层共用）**
- `.u2-art-shade` = `linear-gradient(180deg, rgba(30,18,6,.04), rgba(30,18,6,.06) 40%, rgba(30,18,6,.42) 100%)`
  \+ `radial-gradient(70% 50% at 50% 18%, rgba(255,255,255,.22), transparent 70%)`（与 `ui-v2-spec §5.2` 同一套）。
- 这一层负责把「人」和「景」压到同一明度，并让下沿更暗 → 卡面正文更跳。**所有场景走同一层，色调自然统一。**

**抠图友好约束**：角色头发/衣物与背景对比 **≥25 L 点**；人物外轮廓收 **2px 深咖描边（#3a2a18，40%）**，
既是桌游风卡面的描边语言，也让抠图边缘干净（不需要发丝级精修）。

### 1.5 阴影落点

- 椭圆地面影：画布 **宽 260 / 高 30**（显示 125×14），中心 **(320, 678)** 与脚底基准线重合，
  `radial-gradient(closest-side, rgba(90,40,10,.35), transparent)`，不透明度 35%。
- 场景必须在地面区（y 600~720）画一条**地面接缝/桌沿/地砖线**，让影子落在"地"上而不是浮在墙上。
- 无人物卡（§5）不放地面影。

### 1.6 焦点位（无人物卡与道具层的落点）

- 定义：以 **(50%, 62%)** 为中心、**40% 宽 × 30% 高** 的矩形区域（显示约 124×105）。
- 场景出图时在这个位置安排「桌面/屏幕/信封/手机」等承托物，物件层（或 emoji 占位）就落在上面。
- 例：`trading_desk` 的焦点位是显示器下方桌面；`kitchen_table` 是账单摊开的中心；`doorway` 是门把手/快递箱。

### 3.4 laopo 现有 5 张怎么迁进新模型

现状：`assets/char/laopo{,_happy,_angry,_cry,_worry}.webp`，**560×640、无 alpha**。

| 步骤 | 动作 |
|---|---|
| 1 | 从 `assets/char/raw/` 的 1024×1024 源图（同样无 alpha）抠像。若抠像质量不够，按现有角色设定重出一版**透明底** |
| 2 | 统一到 **640×720 画布**：等比缩放至人物高 560，脚底对齐 y=678，脸中心对齐 (320, 202) |
| 3 | 导出透明 WebP q80，base ≤38KB、差分 ≤36KB |
| 4 | 差分**必须与 base 同坐标同构图**（同一 PSD 换表情层导出），代码不做任何锚点拼接 |

**过渡期（批次 2 交付前）—— flat 模式**：
manifest 里 `"flat": ["laopo"]` 的角色，前端**跳过场景层与人物层**，把整幅 560×640 图直接 `cover` 铺满图位
（等于"自带场景的整图"）。观感差异可控（都是暖调插画），但**必须在批次 2 里消灭**：
32 张卡 = 19.4% 的曝光，长期留 flat 会让两套画面质感并存。

## 4. 差分与 `c.emo` 的对应

实测 `emo` 分布（165 张卡）：**137 张无 emo、14 worry、9 happy、4 angry、1 cry**，
且**全部集中在 laopo**（其他 12 个角色 0 个 emo 卡）。

| `c.emo` | 卡数 | 文件名 | 备注 |
|---|---|---|---|
| 无 | 137（其中 laopo 4 张） | `<whoId>.webp` | base |
| `worry` | 14 | `laopo_worry.webp` | |
| `happy` | 9 | `laopo_happy.webp` | |
| `angry` | 4 | `laopo_angry.webp` | |
| `cry` | 1 | `laopo_cry.webp` | |

规则：
- 文件名仍为 `<whoId>_<emo>.webp`（**v2 的命名保留**，只把扩展名从 png 统一为 webp）。
- 差分数 = 该角色在数据里实际出现的 emo 种数。**不为"可能用到"预制**——新卡加了 emo，补一张同名文件即可。
- 差分图必须与 base **同画布同锚点**（头顶 118 / 脚底 678 / 脸 (320,202)），只有表情区域不同。
- 走复用映射的角色（§3.2）不单独出差分。

## 5. 没有专属角色的卡怎么办（165 卡全都有画面）

四类桶，实测卡数：

| 桶 | 卡数 | 占比 | 画面构成 | 举例 |
|---|---|---|---|---|
| **A 专属/复用人物** | **85** | 51.5% | 场景 + 人物 | 老婆、老妈、老板… |
| **B 剪影** | **13** | 7.9% | 场景 + 剪影（单/群） | 自己、所有人、大 V、司机 |
| **C 无人场景 + 物件焦点位** | **56** | 33.9% | 场景 + 焦点位物件（先 emoji，后道具图） | 新闻、猫、体检报告、账单、短信 |
| **D 纯空镜** | **11** | 6.7% | 只有场景，什么都不加 | 「女友搬走了」（空衣柜）、「凌晨三点」、生日、地漏、周末、停电 |

- **C 类先用 `avatar` 字段的 emoji 占位**：把卡片自带的 emoji（📰 🐱 📉 📱 🧾 🩺 …）渲染在焦点位，
  尺寸 72px、带同等地面影，观感像"桌面上的一个物件"，不是空盒子。**这不需要任何新素材**，先上线。
- C 类升级（批次 5，可选）：10 张道具图替换 emoji，命名 `assets/prop/<key>.webp`。
- D 类**什么都不加**——空镜本身就是叙事（空衣柜、黑着的屏幕）。这 11 张卡靠场景构图与文案承担情绪，
  不许为了"热闹"硬塞人影。
- 判定用 manifest 的 `roster` / `silhouette` / `props` 三张表，**不猜、不探测文件**（小程序无法判断文件是否存在）。

```json
  "canvas": [640, 720],
  "scenes": {
    "伴侣": "living_night", "家人": "living_night",

             "tijian": "prop_report", "xinyongka": "prop_bill", "shouji": "prop_phone" },

```

**逐卡解析顺序（前端照这个写，不许改顺序）**：
1. `overrides[card.id]`（手工覆盖，默认空对象，只给"tag 与画面不符"的个别卡用）
2. 人物：`flat` → `reuse[whoId]` → `roster` → `silhouette[whoId]` → 无人物
3. 场景：`scenes[tag]` → `sceneDefault`
4. 道具：`props[whoId]`（仅当无人物时）

伪代码：
```js
function artOf(card){
  const o = ART.overrides[card.id] || {};
  const sceneKey = o.scene || ART.scenes[card.tag] || ART.sceneDefault;
  if (ART.flat.indexOf(card.whoId) > -1 && !o.char) {
    return { mode:'flat', src:'/assets/char/' + card.whoId + '.webp' };  // 整图铺满，不叠场景
  }
  let who = o.char || ART.reuse[card.whoId] ||
            (ART.roster.indexOf(card.whoId) > -1 ? card.whoId : null);
  if (!who && ART.silhouette[card.whoId]) {
    return { mode:'sil', scene:'/assets/bg/scene_' + sceneKey + '.webp',
             sil:'/assets/char/' + ART.silhouette[card.whoId] + '.webp' };
  }
  return { mode: who ? 'person' : 'scene',
           scene:'/assets/bg/scene_' + sceneKey + '.webp',
           person: who ? '/assets/char/' + who + (card.emo ? '_' + card.emo : '') + '.webp' : null,
           prop: (!who && ART.props[card.whoId]) ? '/assets/prop/' + ART.props[card.whoId] + '.webp' : null };
}
```
- **回落**：`<image binderror>` 时把该层置空（人物层出错只丢人物，场景层出错用纯 CSS 渐变兜底），
  绝不出现破图标；占位与真图**版式完全一致**（图位尺寸、圆角、内衬线、下沿暗层都不变）。
- 换素材不动代码：文件替换即生效；新增角色只需把 whoId 加进 `roster`。

# 附录 A · 美术素材规范 v2（2026-10-28，已被 v3 取代）

> 以下为 v2 原文，仅作历史对照。与 v3 冲突处以 v3 为准（逐条对应见上面 §10）。

# 美术素材规范（v2 · 轻量版）

> 2026-10-28 第二版。v1 按「整屏立绘 + 全角色差分」算账，84+ 张图、做完 3MB+，小程序扛不住。
> v2 按**实机测量 + 包体预算**重算：卡面根本放不下大立绘（实测见下），一个人物一张图就够，
> 表情差分只给出场最密的角色。目标：**第一批 11 个文件 ≈ 500KB 撑起门面**，完全体 ≤ 1.3MB。

## 0. 实测结论（为什么 v2 这么轻）

用 Playwright 在 375×812 / 360×640 / 320×568 三档机型实机测量：

- 卡面内宽 **274 逻辑px**；HUD 压成一行图标 + 卡顶「谁在说话」行和常驻选项
  全部删掉后（2026-10-28 三次实测），人物位 **274×325（竖版 0.84:1，王权式）**；
- 卡面文字最多两行 = 55px，**文字永远完整**（文字优先排版，图吃剩余空间，
  极端 4 行文字时图缩到 178px 仍不溢出）；
- 结论：**整屏大立绘（v1 的 750×1000）塞不进卡面**，出图只会浪费包体。
  卡面要的是一张「人物半身竖版图」，**560×640** 足够。

## 1. 通用规格

| 类别 | 显示尺寸（逻辑px） | 导出尺寸 | 格式 | 单张体积预算 |
|---|---|---|---|---|
| 卡面人物图 | 274×325，文字长时自动缩 | **560×640**（竖版 7:8） | **WebP（带透明）**，兜底 PNG-8 | **≤ 45KB** |
| 表情差分 | 同人物图 | **560×640，同构图** | 同上 | ≤ 45KB |
| 主菜单背景 | 375×812 全屏 | **750×1624** | JPG q80 | ≤ 120KB |
| UI 图标 | 16–22 | SVG 矢量源文件 | SVG | 不占包体 |
| BGM | — | MP3 128kbps 无缝循环 | — | ≤ 500KB/首 |
| 音效 | — | MP3 96kbps ≤ 2s | — | ≤ 20KB/个 |

- **设计基准 375 逻辑宽，导出 @2x**。人物图不用 @3x：640 已够 375 屏显示
  （显示宽 274，640 = 2.3x），@3x 白多体积。
- **格式必须 WebP 或 PNG-8（pngquant 量化）**：人物要抠图叠在渐变底上，
  PNG-24 一张 100–150KB，15 张直接爆 2MB 主包；WebP 带透明约 25–40KB。
  微信小程序 `image` 组件 2019 年起全平台支持 WebP，放心用。
- 人物图安全区：**左右各 4% + 底部 8%** 可能被 cover 裁掉（文字变长时图从底部让位，
  人物上半身永远安全）；
  **脸中心锚点放在 (50%, 28%)**，脸宽约占图宽 22%——这是表情差分对齐的基准线。

## 2. 命名规则（零映射表）

```

assets/char/<whoId>_<emo>.png      表情差分：assets/char/laopo_angry.png
assets/bg/<场景>.jpg               背景：assets/bg/menu.jpg
assets/ico/<名称>.svg              图标：assets/ico/mind.svg
assets/bgm/<场景>.mp3 / sfx/<动作>.mp3
```

## 3. 机制说明（代码已实现，素材未到不塌版）

- **占位**：没图的卡显示角色 emoji（放大居中 + 渐变底），版式与有图时完全一致，
  玩家看不出「缺素材」。实测截图确认过，观感自然。
- **接图**：文件放进 `assets/char/` 后，把 `prototype.html` 里 `ART_ON` 改 `true`
  （或临时用 `?art=1` 预览）即全局生效；单图 404 自动塌回 emoji 占位，不留破图。
- **表情差分**：卡数据可选字段 `emo`（如 `"emo": "angry"`），有它就加载
  `<whoId>_<emo>.png`，没有就加载底图。差分图**必须与底图同尺寸同构图**——
  画师在同一个 PSD 里换表情图层导出，天然对齐；代码不做任何锚点拼接。
- **演示已就位**：老婆 4 张卡标了 emo（纪念日 happy / 质问 angry / 离婚 cry /
  吃饭 worry），配套测试图验证过切换链路，素材到位直接替换同名文件。
