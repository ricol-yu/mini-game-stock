# UI 适配与体验规范（ui-adaptation）

> 2026-11-03 · 体验设计。读者：改 `prototype.html` 的前端、后续做小程序迁移的工程师。
> 配套：`ui-v1.md`（结构）、`art-asset-spec.md`（素材）、`AGENTS.md` 卡面版式铁律。
> **各区块高度基线以 `design/ui-v2-spec.md` §2.1 为准**（mkt 158 / HUD 48 / strip 26 / 外边距 14）；
> 本文 §1.3、§1.5 已于 2026-11-03 按 v2 高度重算（v1 的 mkt 112 版数值已全部替换）。
> 本文只回答一个问题：**同一套界面，怎么在 320~430 宽、568~932 高的所有机型上不塌**。

## 0. 结论速查

| 问题 | 结论 |
|---|---|
| 设计基准 | 宽 **375**、高 **812**（逻辑 px），卡面画布 **640×720**（2.07x，art-spec v3） |
| 尺寸单位 | **固定逻辑 px + flex 弹性分配**。不用 vw/clamp——卡牌是比例组件，1px 描边和 16px 正文字号不可缩放，缩放交给 flex（图区吃剩余空间） |
| 卡区最小高度红线 | 卡总高 **< 170px** 时图区整块隐藏（`.art{display:none}`），文字 `flex:1` 顶满；卡面正文任何档位保底 **2 行 = 55px**（16px × 1.72） |
| 小屏缩的顺序 | ① tape 46→36 → ② **tape 整块隐藏** → ③ 图区地板放开为 0（剩余 <64px 整块收起） → ④ HUD 行 48→40 → ⑤ 图区整块隐藏 → ⑥ `.fn` 行隐藏（阈值见 §1.5；<360 宽直接走 ②）。**玩法文字与选项永不砍** |
| 需要砍掉的内容 | 无。五档只有 SE1（320×568）触发降级，且只砍 tape 一个装饰区块；砍完图区回到 181，正文 2 行完整。其余四档 stage ≥349，一档不触 |
| 单位细则（小程序） | 布局尺寸 rpx；**字号、1px 描边、阴影、手势阈值/位移一律 px**（§3.1） |

## 1. 设备矩阵与画布策略

### 1.1 目标机型表

| 档位 | 逻辑分辨率 | statusBar | 底部安全区 | 优先级 |
|---|---|---|---|---|
| iPhone SE1 | 320×568 | 20 | 0 | 保底不塌即可 |
| iPhone SE2/3 | 375×667 | 20 | 0 | **必测** |
| iPhone 12~14 | 390×844 | 44~47 | 34 | **基准机** |
| iPhone 14/15 Pro Max | 430×932 | 47（灵动岛机型 54） | 34 | 必测 |
| 主流安卓小 | 360×800 | 24~32 | 24（手势条） | **必测**（低端安卓另见 §5.2） |
| 主流安卓大 | 393×851 | 28~36 | 24 | 必测 |
| 折叠屏展开态 | 480~700 宽 | — | — | 按 §1.4 封顶策略，不做专门适配 |
| PC 微信 | 414×736 固定手机视图 | — | — | 不配 `resizable`（铁律），零投入 |

### 1.2 画布策略结论

- **固定 px + flex**。原型现有排版体系（`.art` `flex:1 1 auto` 吃剩余空间、`.txt` 自然高度）就是正确答案，适配只调「剩余空间给多少」，不引入任何缩放单位。
- 宽度方向：区块左右边距固定（stage 16、mkt 16、HUD 12——v2 spec §2.2），内容随屏宽自然伸缩；卡内宽 375 档 = **309px**（375−32−34，v2 口径）、360 档 = 308px、320 档 = 268px，差异全被图区吸收。
- 宽度 **< 360px**（仅 SE1）四处收紧：`stage` 边距 16→12、`mkt` 边距 16→10、卡内距 14→12、**tape 直接隐藏**（mkt 158→112，与 §1.5 的 stage<270 规则等效，按宽度写更省事、也不会抖）。
- **折叠屏/宽屏**：内容列封顶 `max-width:480px` 水平居中，绒布底（v2 视觉）铺满整屏延伸到边缘。不做双栏、不做平板布局（resizable 铁律 + 一张全屏卡的玩法形态决定了这是唯一解）。

```css
/* 小程序 page 根 / 原型 clean 模式通用 */
.page-bg{ background:var(--felt); }            /* 绒布底铺满全屏 */
.page-col{ max-width:480px; margin:0 auto; }   /* 内容列封顶居中 */
```

- 其余四档 stage ≥349、图区 ≥234，**全量内容，一档不触**；降级阶梯是给异形 webview / 折叠屏半开态兜底的。
- 图区显示尺寸 vs 导出画布：390 档 309×350、430 档 364×431。**art-asset-spec v3 统一 640×720 画布（场景层与人物层同坐标）**，对 309 宽是 2.07x、对 350 高是 2.06x——不再有 v2 的 560×640 一档，也不存在「Pro Max 上偏软」的问题。
- 网页原型阶段（`.nav` 固定 66px、无状态栏无安全区），clean 模式各档 stage 比上表多 6~27px，只会更宽裕。

### 1.4 折叠屏与超宽屏

微信在折叠屏展开态会以展开宽度运行小程序。策略一条：内容列 480px 封顶居中（§1.2 代码），绒布底延伸。**不做**任何 700px 宽的专属布局；展开态等同「430 Pro Max 的居中版」。

### 1.5 降级阶梯（按 stage 实测高度触发，写进布局 JS）

启动时算一次：`stageH = winH − navH − hudH(48) − stripH(26) − mktH(158) − 14 − safeBottom − 12`。
**判定只用启动值按顺序套一次，不递推**（否则每缩一档 stage 变高又会退出降级，来回抖）。

| 触发条件 | 动作 | 回收高度 |
|---|---|---|
| stageH < 300 | tape 46→36，mkt 158→148 | +10 |
| stageH < 270 | **tape 整块隐藏**（`.tape{display:none}`），mkt 158→112 | +46 |
| stageH < 260 | **图区地板放开为 0**（`.art{min-height:0}`，2026-11-03 终版，撤掉 96 地板——96 + 3 行正文 83 + fn 17 + 卡内距 40 ≈ 236，卡高不足时地板会把文字挤出卡外裁掉）；图区剩余 **<64px** 时 JS 挂 `.gone+.hide` 整块收起，`.art.hide + .txt` 吃满卡面垂直居中（不留 30px 图缝） | 图区可让位/整块收 |
| stageH < 230 | HUD 行 48→**40**（图标本体仍 34×32，只压行高；实现 `.phone.deg4 .vit{height:40px}`） | +6 → +8 |
| stageH < 190 | `.art{display:none}`，文字 `flex:1` 顶满（此时卡高恰为 170，红线生效） | 图区全让 |
| stageH < 170 | `.fn` 行（卡底「——」行）隐藏 | +17 |

> HUD 档的阈值故意压到 **230**：SE1 砍完 tape 后 stage 296，已经不缺血，**就不动命**——四条命是玩家唯一的生存读数，能不动就不动。这一档留给折叠屏半开态、极小 webview 这类砍完 tape 仍不构的情况。

**为什么 320 档先砍 tape，而不是砍 HUD 或压图**：

1. tape 是这一屏唯一**砍掉不损失任何决策信息**的区块——当日涨跌在净值行（数字+▲▼）、账目行（这一笔 -1,420）、tape 右上 lab 文字（今 +1.5%）三处都有冗余表达，图本身只是形状；
2. 320 宽下 tape 只有 288px，6 个刻度标签已经挤到重叠，读图价值接近 0，留着反而添乱；
3. 砍 HUD 会伤「命」的可读性（四条命是玩家唯一的生存读数），压图会伤门面（人物图是 v2 的视觉支柱），动正文是红线内禁止项。所以从最便宜的那块开始砍。

机型命中情况（按 §1.3 表）：**只有 SE1 命中**（stage 250 → tape 36 → tape 隐藏，终态 stage 296、图区 181，正文 2 行完整，**HUD 不动**——296 ≥ 230）；375/390/430/360 四档 stage ≥349，一档都不命中。

> ✅ **落地状态（2026-11-03，commit 37b0784）**：六档全部落地并与本表逐档对齐（deg1~deg6，只累加不递推）。真 viewport 复测：375×530 / 375×500 的 tape 整块隐藏、mkt 回落、卡区回吃、正文零裁切；四档出货尺寸（375×667 / 390 / 430 无 deg 类、320 走宽度规则 deg1）逐项不变；`--tier` 七档 + smoke 38 项连跑 15 次全绿。**唯一权威实现见 prototype.html L430~465 的阶梯注释。**

文字优先规则（AGENTS 铁律）在每一步都生效：文字自然高度、永远不截断，砍的全是装饰高度。**账目行不要改回叠在分时图上**——独立账目行是已拍板的可读性投资（轮播不再盖分时图），不退回 112。

### 1.6 与美术规格的对账（测量偏差 + 画布统一）

`art-asset-spec.md` §0 记录「375 屏卡面内宽 274」——这是**开发框 `.phone`（344px）的内宽**（344−32−34=278≈274），不是真机 375 宽的数值。真机 clean 模式下卡内宽 = **375−32−34 = 309px**（截图 day1.png 实测吻合）。v3 已按 309 重算，两文档口径一致：

- **画布统一 640×720**（场景层与人物层同坐标），对 309 宽是 2.07x、对 350 高 2.06x，**v2 的 560×640 一档作废**。不要再按 560 规划任何批次。
- **laopo 现有 5 张 560×640 不满足 v3**：它们无透明通道（源 PNG colorType=2），不是「尺寸略小可凑合用」，而是**必须重出带 alpha 版**。laopo 重出排**批次 2**，交付前走 art-spec §3.4 的 **flat 过渡**（整图 `cover` 铺满图位、跳过场景层与人物层）——flat 是临时态，32 张卡 = 19.4% 曝光，不能长期留。
- 真正的**第一批 = 10 张场景 + 2 张剪影**（≈470KB），上线即 165/165 卡有完整画面；这比「先出人物」更快让每一张卡都有画面。
- SE1 降级态图区 181，640×720 图在该档 3.97x 富余，无需另出小图。

## 2. 安全区与沉浸式

### 2.1 顶部：自定义导航 + 胶囊避让

小程序 `navigationStyle: custom` 后状态栏归页面管。**不要写死任何顶部高度**，启动时算：

```js
// pages/game/game.js  onReady 前执行，结果存 globalData
const win = wx.getWindowInfo();
const cap = wx.getMenuButtonBoundingClientRect();
const statusBarH = win.statusBarHeight;
const navH = statusBarH + (cap.top - statusBarH) * 2 + cap.height; // iPhone 12+: 87
const capsuleGap = win.windowWidth - cap.left + 8;                // 内容右缘避让距离
```

| 设备 | statusBarH | navH |
|---|---|---|
| SE1 / SE2/3 | 20 | 60 |
| iPhone 12~14 | 47 | 87 |
| 14/15 Pro Max（灵动岛） | 54 | 94 |
| 安卓主流 | 24~36 | 64~80 |

- 导航内容行（标题 + 返回/暂停按钮）高 = navH − statusBarH，即固定 **40**（胶囊 32 + 上下各 4）。
- 页面所有自绘内容（HUD、胶囊条、行情区）右缘 ≤ `windowWidth − capsuleGap`，**任何东西不得进入胶囊的 32px 高度带**。现布局 HUD 全宽、但四命图标居中分布，最右图标中心在 7/8 屏宽处 ≈ 341（390 档），距胶囊左缘仍 > 30px，安全；加新组件时按这条验。
- **网页原型 clean 模式**（微信 webview 打开时）对应方案：

```css
html.clean .phone{ height:100vh; height:100dvh;   /* dvh 防 webview 工具条抖动 */
  padding-top:env(safe-area-inset-top);
  padding-top:calc(env(safe-area-inset-top) + constant(safe-area-inset-top) * 0); /* 旧 iOS 兜底 */
}
```

### 2.2 底部：Home indicator

- iPhone 底部安全区 **34px**（安卓手势条 24px），全部用 `env(safe-area-inset-bottom)`，不写死 34。
- **可交互元素**（结局页「再来一辈子」按钮、暂停按钮、弹窗按钮）：距物理屏底 ≥ 安全区 + **8px** 视觉间隙（390 档即 ≥42px）。
- **非交互**（卡底 `.fn` 行、toast）：≥ 安全区 + 4px。
- **卡牌拖动区**：`.stage` 底边距 v2 是 12（v1 的 8 已废弃），卡内下 inset 16（留给牌背露出），两者都不吃安全区：`margin-bottom: calc(12px + env(safe-area-inset-bottom))`。飞出动画 −460px 是水平向，不受影响。

```css
.stage{ margin-bottom:calc(12px + env(safe-area-inset-bottom)); }  /* 小程序 WXSS 同写法 */
.btn{ margin-bottom:calc(env(safe-area-inset-bottom) + 8px); }
```

### 2.3 左右：圆角屏

- 内容距左右 ≥ 16px（现状：stage 16、mkt 14——mkt 提到 16 统一），圆角屏屏幕圆角半径 ~40px 只切到四角，现有边距已避开。
- 绒布底/背景色必须 `background` 铺满到物理边缘（含安全区），内容才做 inset——沉浸式是「底满、content 让」，不是「整页缩进来」。

## 3. 小程序原生落地注意（WXSS 特有坑）

### 3.1 px vs rpx 取舍规则

| 用 rpx（×2 自 375 设计稿） | 用 px（写死） |
|---|---|
| 区块宽高、边距、圆角（随屏等比） | **所有 font-size**——大屏字不许放大（行数失控）、小屏不许缩小（可读性） |
| HUD 图标、图区 min-height、tape 高 | **1px 描边/分隔线**——375 屏 1rpx=0.5 物理px，部分机型渲染丢失或发虚 |
| 卡片圆角、stage 边距 | **box-shadow** 偏移/模糊/扩散 |
| 图区、mkt 内部间距 | **手势相关的一切**：松手阈值、translate 位移、rotate 系数——WXS 拿到的 touch 坐标是 px，布局若 rpx，阈值和卡宽会差一个比例（§4.2 的阈值公式按卡宽 px 算） |

速查：设计稿 375 上量到的 px × 2 = rpx；`1px` 线和阴影照抄 px。

### 3.2 page / app 配置（直接抄）

```json
// app.json —— 注意：绝不配置 "resizable"。
// 原因（铁律）：配了 PC 端宽窗口会自动双栏，一张全屏卡被拆两栏，视觉直接崩；
// 且大屏模式不支持自定义导航。PC 就让它显示手机视图。
{
  "window": {
    "navigationStyle": "custom",
    "pageOrientation": "portrait",          // 禁横屏，写死
    // 回弹色必须等于绒布渐变外缘 --u2-felt-3 = #0c2b1e（v2 spec §2.3）。
    // 写成绒布主色 #17402f 或旧值 #0b3d2e，上滑回弹时会露出一条色差，沉浸感当场破功。
    "backgroundColorTop": "#0c2b1e",
    "backgroundColorBottom": "#0c2b1e"
  }
}
```

```json
// pages/game/game.json
{
  "navigationStyle": "custom",
  "disableScroll": true,                    // 游戏页整页禁滚，滑卡手势不与页面滚动打架
  "enablePullDownRefresh": false            // 显式关下拉刷新
}
```

二级页（设置/图鉴，若做）单独 `pageOrientation` 继承全局即可；它们是可滚动列表页，`disableScroll` 不要带过去。

### 3.3 键盘

游戏内**没有输入框，保持没有**。设置页「删除存档需输『确认』两个字」（ui-v1 原案）改为**两步按钮**：点「删除存档」→ 按钮变红「再点一次确认」，3 秒未点复原。理由：键盘弹起 300ms 内顶起 fixed 布局、游戏页 disableScroll 后光标定位诡异，为一个删档确认不值。

若未来必须加输入框：`<input adjust-position="{{false}}" cursor-spacing="16" />` 并给弹窗容器手动 `translateY(−键盘高)`（`wx.onKeyboardHeightChange`），绝不依赖默认顶起。

### 3.5 切后台 / 回前台：日结算保护（重点）

**先说事实**：本游戏是回合制——`tick()` 只在 `fly()`（出牌）里被调用，**没有任何 wall-clock 驱动的数值变化**，切后台一天回来不会多扣一分钱。这个架构是保护本身，升级为铁律级约束：

1. **永远不许引入按真实时间驱动的经济变动**（不许「离线收益」「挂机扣房租」这类设计）。
2. `setInterval` 只允许用于展示层（账目行 ledg 轮播、动画），**onHide 必须全部 clear**，onShow 重启：

```js
// pages/game/game.js
onHide(){
  this._timers.forEach(clearInterval); this._timers = [];
  this._bgm && this._bgm.pause();
  wx.setStorageSync('save', S);            // 存档兜底（日常存档仍挂在每日结算后）
},
onShow(){
  // 不做任何时间补偿结算——数值只由出牌驱动
  this._bgm && this._bgm.play();
  this.startLedger();                      // 重启展示层轮播
}
```

3. BGM 用 `wx.createInnerAudioContext()`，onHide 暂停 onShow 续播（不销毁重建，避免 Android 上从头播）。

### 3.6 首屏加载

**字体**：不引外部字体（中文字体全量 5MB+，直接爆主包）。系统字体栈：

```css
page{ font-family:-apple-system,"PingFang SC","HarmonyOS Sans SC","MiSans",
      "Microsoft YaHei",sans-serif; }
```

桌游感的字重这么保：**标题 letter-spacing 3px + font-weight 800 + 描边/印章感全靠 border 和 box-shadow（粗描边是 v2 视觉的支柱，不依赖字体）**；若标题要装饰字，出一张 PNG 图（≤20KB），不嵌字体。低端安卓 PingFang 缺失会退到 MiSans/雅黑——**验收时在低端安卓上看 700/800 字重是否仍在**（部分老机型只有 400/700 两档，fallback 到 700 即可接受）。

**图片**：全部 `lazy-load` 的 `image` 组件；卡面走 v3 两层合成（场景层 + 人物层，各 **640×720 WebP q80**，人物层必须带 alpha，两层同坐标、不逐场景调位置）；laopo 重出前用 `manifest.flat` 的整图过渡；首屏 3 张教程图 `tut_*` 在包内无需预载逻辑；CDN 图（若分包后）靠 image 组件自带缓存。

**分包**：音频单独分包（art-spec §5 泄压阀①），并配预下载：

```json
// app.json
"subpackages": [{ "root": "assets-audio", "name": "aud", "pages": [] }],
"preloadRule": { "pages/game/game": { "network": "wifi", "packages": ["aud"] } }
```

主包预算（v3 口径）：代码+卡数据 ~180KB + **第一批素材 470KB（10 场景 + 2 剪影）** + 分享图 80KB ≈ 730KB，距 2MB 编译上限余量充足；后续批次贴着红线时按 art-spec §5 的泄压阀（音频分包 → BGM 压 96kbps 单声道）处理，不砍图。

## 4. 手势与手感

### 4.1 滑卡热区与边缘误触

- **热区 = 整个 `.stage`**（卡面 + 上 4 / 下 16 的牌背缓冲，v2 卡 inset 4/16）。toast 已 `pointer-events:none`，不抢手势；`.tip` 悬浮层同改 pointer-events:none（§4.3）。
- **顶部边界**：`.stage` 从 nav 底开始，胶囊（系统控件）在 nav 行内，物理上不重叠。禁止把卡区上探进 nav 行来「多要高度」。
- **iOS 侧滑返回**：首页是页面栈根，无冲突。**二级页（设置/图鉴）**：手势起点距屏幕左缘 < 24px 不启动任何拖动逻辑（iOS 侧滑返回热区 20~30px）。滑卡只发生在游戏页（栈根），现状即安全；若未来游戏页上叠加可返回的弹层，弹层自己 `catchtouchmove` 阻断透传。

```js
// WXS touchstart 里第一行
if (e.touches[0].clientX < 24 || e.touches[0].clientX > winW - 24) return; // 边缘不启动
```

### 4.2 手感参数标定流程（真机调试 2.0，铁律落地 checklist）

原型现状初值（仅作起点，**模拟器上不定型**）：松手阈值 |dx|>78px、rotate = dx×0.045°、纵向跟随 0.25、印章 opacity = |dx|/90、飞出 460px/.34s ease-out、回弹 .32s cubic-bezier(.3,.9,.3,1)。

阈值随屏宽改比例式：`threshold = clamp(卡宽(外层) × 0.22, 64, 94)`——320 档卡宽 296 → **65**，375 档 343 → **75**，390 档 358 → **79**，430 档 398 → **88**。（原型 78 是在 344 开发框上量出来的，换算比例 0.227，与上式一致。）

标定 checklist（顺序执行，每步过了才下一步）：

1. [ ] 开发版内置调试面板（testing.md §三）：连点版本号 5 次开启，显示 fps / touchmove 每秒次数 / dx / WXS 帧耗时
2. [ ] 真机两台：iPhone（12 级）+ 低端安卓（骁龙 6 系 / 4GB）
3. [ ] **跟手**：慢拖卡，卡与手指间无可感知延迟（WXS 帧耗时 < 16ms）；低端安卓若掉帧，给 transform 加 0.9 阻尼系数再测
4. [ ] **松手阈值**：快滑 20 次 + 慢滑 20 次 × 两台机。判据：误触发（<10px 轻点被判出牌）≤ 1 次；漏触发（明显滑出但不响应）≤ 1 次。不过就调比例系数 0.20~0.25 重测
5. [ ] **回弹/飞出**：慢滑不达阈值松手，回弹无弹跳过冲；出牌飞出 ≤ 360ms 且印章定格清晰
6. [ ] 每轮标定结果记录：参数值 + 机型 + 日期，写进 `docs/devlog/` 最新一篇
7. [ ] 任何参数改动后，下次发版前按 3~5 重跑一遍

### 4.3 无障碍

**触达（44×44）**：

| 元素 | 现状 | 改法 |
|---|---|---|
| HUD 四命图标 | 视觉 34×32（v2） | **点击热区补到 44×44**（透明外扩，图标本体不放大） |
| 状态胶囊 chip | 高 ~22 | tip 触发改**点击**（见下），chip 本体做 `min-height:32` + 8px 隐形外扩热区 |
| 主按钮 `.btn` | 高 ~44 | 达标，不动 |
| 暂停按钮（新增） | — | 44×44 起 |

**hover 信息改点击弹出**：HUD 数值、账单倒计时明细全在 `:hover` tip 里，触屏上完全不可达（现有 prototype 最大问题之一，§6）。改法：chip / 图标 `bindtap` 切换 `.tip.on`，同一时刻只开一个，点空白处全关；桌面端保留 hover。tip 容器加 `pointer-events:none`（本体），内容层可点。

**系统大字号**：小程序 WXSS 字号不随系统自动变，主动适配：

```js
const fs = wx.getSystemInfoSync().fontSizeSetting || 16;   // 默认 16
this.setData({ bigFont: fs >= 19 });
```

```css
.big .card .txt{ font-size:18px; line-height:1.7; }   /* 字变大 */
/* 图区不给地板（min-height 保持 0）：大字号 5 行在 SE1 卡 276 上 96+137+57=290 会裁字，
   让图缩到剩余空间、剩余 <64px 由 JS 挂 .hide 整块收起（见 §1.5 档 3）。
   96 只当高度宽裕档的美观下限，不做保底手段。 */
```

**图让位时的裁切锚点（2026-11-03 补，与 visual-architect 对齐）**：图区高度 <200 时（大字号 96 档、SE1 降级终态 181 档）统一改锚点。**注意两档的图区宽度不同，不能混算**：

| 档位 | 图区宽 | cover 缩放后画布高 | 可见带（`50% top`） | 可见带（`50% 16%`） | 结论 |
|---|---|---|---|---|---|
| 大字号 96 档 | 309（390 档宽） | 309÷640×720 = **347.6** | 0~**27.6%** | 11.6%~39.2% | **真修复**：脸心 28%、下巴 34% 正好被切在边线 |
| SE1 181 档 | **266**（320 档：320−24−6−24） | 266÷640×720 = **299.3** | 0~**60.5%** | 6.4%~66.4% | 顺手统一，**不修也不切下巴**（34% 距下沿还有 26 个百分点） |

规则（阈值 200px 一次覆盖两档，代价为零）：

```css
.card .art img{ object-position:50% top; }        /* 常态：纵向不溢出（宽受限），值无影响 */
.card .art.short img{ object-position:50% 16%; }  /* 图区 <200px：96 档 11.6~39.2% / 181 档 6.4~66.4% */
```

由布局 JS 在算完图区高度后给 `.art` 加 `short` 类。**这条只改 UI 锚点，不改素材构图**——640×720 单画布、头顶 16% 写死，不要据此给素材加头部余量。若不愿加类，退路是接受「大字号档只保脸不保下巴」（visual-architect 已把「缩到 309×96 看脸能否认出」写进出图验收第 6 条）。

卡面文字永不截断：不用 `line-clamp`，靠文字优先 flex（长文压图），这是现有版式的天然无障碍优势，保住别破坏。

**色弱（涨红跌绿不只靠颜色）**：

| 位置 | 规范 |

| 一切涨跌数字 | **强制带符号**：`▲ +5,670` / `▼ −1,200`（形状+符号+颜色三重编码）；`0.0%` 用 `—` 灰 |

## 6. 现有 prototype 必须先改的两处（2026-11-03 已全部落地，此节留档供迁移对照）

1. **hover-only tip 携带关键信息，触屏不可达**——已改：chip / 四命图标 `bindtap` 弹出（document 捕获层委托，strip 每日重建不丢事件）、单开互斥、点空白全关不用 mask、tip 本体 `pointer-events:none`、热区补足 44×44、出牌/换卡/结局三个时机强制关闭。迁移时照 prototype.html L1189~1229 的实现搬。
2. **toast 用固定 `top:112px`**——已改：最终方案比本节原稿更好，用**结构解**——`.u2-top` 包裹 nav+HUD+胶囊+行情区，toast `top:100%` 挂在包裹层下缘（落点=行情面板下缘=卡区顶部），HUD/胶囊换行、大字号切换自动跟随，不需要 `--hud-bottom` 测量。落点拍板理由：两行发报 toast 放 HUD/胶囊/净值任何 1~2 行小行都会压关键读数，卡区顶部是唯一空档；toast 2.4s+ 自动消失、瞬态只遮 art 顶部。时长按行数 `min(5000, 1800+400×行数)`；max-width `min(300px, calc(100% − 24px))`（锚点是整屏宽，24px 才正好收进 320 档的 296 内容列）。
